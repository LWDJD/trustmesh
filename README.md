# trustmesh

> 一个**真去中心化**的信任网络运行时。纯 std，零外部依赖，可编进 wasm。
>
> 它最初是为**反女巫**设计的，但同一套结构通过换参数就能做**价值流动**、**内容推荐**——
> 因为核心机制只有一条：**你只能影响你评过分的人，而别人只能通过他们评过的人看到你。**

## 这是什么

一个**库**，不是一个应用，也不是一个网络。

每个节点维护一个 `Engine`：

1. **你的正分清单**：你给谁打过 0~1 的评分（这是唯一信息来源）
2. **你发布的观点**：把「我眼中每个人的可信度」压成 40 KB 定长草图，发出去
3. **你收到的观点**：每轮只取 k 个来源的，按「份额 × 衰减 × 折扣」加权混进你的判断

声望 = **β × 个人项** + **(1−β) × 群体项**，β 默认 0.3。

由此获得的反女巫性质**不是靠算法，是靠结构**：

- 女巫集群自己给自己打满分？**它们不在你的清单里，抽样抽不到，贡献恒为 0**（S1 = 0，8/8 seed 逐位）
- 渗透者给新女巫打满分？**份额 = 评分 ÷ Σ评分，注入越多每个越薄**（S2 越线率 = 0 / 7690 对）

## 它防不住什么（读这段再决定用不用）

| 威胁 | 实测 | 性质 |
|---|---:|---|
| **熟人背叛**：8% 渗透者集体抬举同一个同伙 | **4.37 倍**（最坏观察者 8.14 倍） | β=0.3 的算术后果，**不是 bug** |
| 空账户拿到少量声望 | 2.5% 出现率；**清单 1000 条时 30.4%** | Count Sketch 的碰撞噪声 |
| 单来源自吹 | +83% | 未修 |
| 重放旧观点刷新新鲜度 | ×4.0 | 刻意留给应用层（需要签名） |

**完整的威胁模型见 [审计/威胁模型.md](审计/威胁模型.md)。部署前必读。**

### 「女巫淹没网络」挡得住吗（分两层，答案不同）

**先分清两种「淹没」——它们的负责人不同：**

| 淹没的类型 | 谁负责 | 本库挡不挡得住 |
|---|---|---|
| **内容层**：垃圾内容淹没好内容 | **应用层**（本库不排序内容） | ❌ 不在本库范围 |
| **传输层**：女巫接管网络，正常节点发现不了正常节点 | **应用层做协议 + 本库给原料** | ✅ 关键那一块挡住了 |

### 传输层淹没（作者真正关心的那个）

| 情况 | 实测 |
|---|---|
| **100% 请求失败 × 30 轮** | 引擎不崩、不忘、不停；`query` 前后**最大绝对差 0.00000000**；第 31 轮仍发请求 |
| **全部朋友被冒充、投伪造观点** | 清单仍是 8 条、女巫仍进不来；群体项被污染（女巫/朋友比值 0.29） |
| **发现协议被劫持**（对端谎报「网络只有我们」） | **`shares()` 提供对端无法篡改的引导名单**：条数 8→8、内容变化 **0 条** |

**关键分界**：攻击者能伪造「朋友说了什么」，**伪造不了「谁是我的朋友」**。
正分清单、份额、引导名单 `shares()` 全部只由**你自己的 `rate`** 产生。

**应用层的三条硬要求**（不照做的话本库对传输劫持毫无帮助）：

1. 节点发现**从 `shares()` 起步**，不要从对端学名单；
2. 观点**必须签名验证**（本库不做验签，`设计规格.md` §0.2 归应用层）；
3. 每个候选**多路尝试**（`shares()` 不知道谁在线）。

**内容层**（垃圾内容淹没好内容）：**不在本库范围**——本库只算「谁可信」，不排序内容。
应用必须自己做内容去重 / 限流。本库零此类代码是**刻意的**（`设计规格.md` §0.2 的职责边界）。

### 内容层：即使不归本库，也量化了它能减损多少

| 威胁 | 实测 |
|---|---|
| 大量**陌生**垃圾账户自我吹捧 | **20 万个 ⇒ 我看到的垃圾均值与最高都是 0.000000** |
| 垃圾靠**数量**抢可信度 | **垃圾/诚实恒为 0.50**（我给它评的分数），40 个与 800 个一样 |
| 垃圾靠**我信任的人**背书 | **背书占比 50% ⇒ 垃圾/诚实从 0.50 涨到 0.98**（这是真正的软肋） |

虽然内容排序不归本库，但**「谁可信」这一半本库算得很干净**：陌生垃圾 20 万 = 0 是逐位实测的。
应用层拿这个可信度去排序时，至少不会被「数量」骗到——只会被「我信任的人被收买」骗到。

完整实测见 [审计/传输淹没.md](审计/传输淹没.md)、[审计/淹没实验.md](审计/淹没实验.md)。

## 快速开始

~~~bash
cd crates/engine && cargo run --example quickstart
~~~

例子跑通应用层必须做的五件事：intern → rate → tick → on_view → query。

## 结构

七个**互相独立、零外部依赖**的 crate，每个都是自己的 workspace：

| crate | 职责 | 测试 |
|---|---|---:|
| [`tm_store`](crates/store) | 账户表、正分清单、轮次抽样 + 退避、状态导出 | 157 |
| [`tm_view`](crates/view) | Count Sketch 定长压缩观点（2048×5 f32 = 40 KB） | 51 |
| [`tm_agg`](crates/agg) | 指数衰减、聚合（Mean/Median/WeightedMedian/Trimmed）、β 混合 | 63 |
| [`tm_engine`](crates/engine) | 运行时：badlist 受害者反馈、判据、抽样预算、状态快照 | 206 |
| [`tm_sim`](crates/sim) | 社会仿真：人口/兴趣/同质性/社团/攻击者编排 | 130 |
| [`tm_exp`](crates/exp) | 端到端实验装置（26 个 bin） | 29 |
| [`tm_mincore`](crates/mincore) | **最小反女巫内核原型**：定长稀疏表（cap×6+2 B）替代 Count Sketch；S1/S2/S4/S6 全面优于现行实现，体积小 14~50 倍 | 17 |

能力矩阵 **694 passed / 0 failed / 1 ignored**（七个 workspace）。

**全部零外部依赖**——`[dependencies]` 里没有第三方 crate。这是刻意的：供应链攻击面最小化。

## 参数化：一套结构，多种用途

| 用途 | β（个人:群体） | 半衰期 | 聚合 | k / T |
|---|---:|---:|---|---|
| **反女巫** | 0.3（作者定） | 72h | Mean | 大 / 长（尽量不分裂） |
| 内容推荐 | 0.7~0.9（重个人兴趣） | 720h | Mean | 中 / 中 |
| 价值流动 | 0.5 | 24h | **Median**（抗单点操纵） | 大 / 短 |
| 反垃圾 | 0.5 | 168h | Trimmed | 中 / 中 |

这些都是**现有引擎能直接配出来的参数组合**，不需要新机制。

## 部署前检查清单

- [ ] **清单长度 ≤ 300**（否则空账户问题爆发，m=1000 时 30.4% 空账户进分布）
- [ ] **抽样节奏满足** `(n_list/k)·T ≤ H/2`（用 `Engine::freshness_stats` 自查）
- [ ] **`on_view` 只投递真正的新观点**（重放会刷新新鲜度）
- [ ] **应用层保证观点来源可信**（库不验签）
- [ ] **接受 S3**：背书场景 4.37 倍
- [ ] **限流 / DDoS / 内容托管**由应用层负责

## 构建与测试

**一条命令跑完全部检查**（推荐）：

~~~powershell
.\verify-all.ps1
~~~

它会跑七个 workspace 的测试、文档测试、clippy、以及 wasm32 逐位对拍，最后打印汇总。

**手动跑某个 crate**（每个 crate 是独立 workspace，要分别 cd 进去）：

~~~bash
cd crates/store && cargo test
cd crates/view  && cargo test
cd crates/agg   && cargo test
cd crates/engine && cargo test
cd crates/sim   && cargo test
cd crates/exp   && cargo test
~~~

⚠️ **不要只在根目录跑 `cargo test`**——根目录是 v1.0 旧代码，只有 58 条测试。
上面七个 crate 是独立的 workspace，根目录的测试**不会**覆盖它们。这是新人最容易踩的坑。

### wasm32 逐位对拍

~~~powershell
cd tools\wasm-smoke
.\run-all.ps1
~~~

证明**整个引擎**（不是某个纯函数）在 wasm32 与 native 上给出逐位相同的声望值。
