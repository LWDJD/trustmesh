# tm_agg —— 衰减与聚合

trustmesh 的数值层：只做三件纯计算的事，没有 I/O、没有线程、没有全局状态、**没有任何外部依赖**（只用 std）。

```rust
pub fn decay(dt: u64, half_life: u64) -> f32;
pub fn aggregate(items: &[(f32, f32)], mode: AggMode) -> Option<f32>;  // items = (权重, 数值)
pub fn combine(beta: f32, personal: Score, group: Option<Score>) -> Score;
```

| 函数 | 语义 | 规格要点 |
| --- | --- | --- |
| `decay` | `0.5^(dt/H)` | dt=0→1.0，dt=H→0.5，dt=2H→0.25；恒 >0、非 NaN；H=0 按 1 处理 |
| `aggregate` | 四种口径聚合来源观点 | 剔除权重≤0 或非有限项；结果 clamp [0,1]；空列表 None |
| `combine` | `β·个人项 + (1−β)·群体项` | β clamp [0,1]；group=None 按 0；β=1 精确等于 personal |

四种口径：

* `AggMode::Mean` —— 加权平均 `Σ(w·v)/Σw`。
* `AggMode::Median` —— 普通中位数，不看权重的大小。
* `AggMode::WeightedMedian` —— 按数值升序累计权重，取首次 **≥ 总权重一半** 处的数值（下侧中位数）。
* `AggMode::Trimmed(p)` —— 两端各裁掉 p 比例权重，再加权平均；p clamp 到 `[0, MAX_TRIM]`。

## 数值约定

* 入参与返回都是 `f32`；**中间累加一律 f64**，只在出口转回 f32。来源可能有几百个，f32 连加会积累可见误差。
* 对外数值一律 clamp 到 `[0,1]`；**NaN 一律当 0**（0 在本协议里就是「没表态」，是最保守的语义）。
* 衰减在极端 dt 下会下溢，用 `DECAY_FLOOR = f32::from_bits(1)`（≈1.4e-45）兜底，保证「指数衰减永不精确归零」在工程上成立。
* `MAX_TRIM = 0.5 − ε/2`：p = 0.5 会把权重裁光，因此上限取到略小于 0.5。

## 单点操纵实验（20 个来源，1 个撒谎者）

场景：**20 个来源，1 个撒谎者给 1.0，19 个诚实来源给 0.0**。
诚实来源权重恒为 1.0（19 个来源从头到尾都在列表里，不会因权重归零被剔除），只放大撒谎者的权重。
复现：`cargo test --test sybil_report -- --nocapture --test-threads=1`

### 表 1：撒谎者权重占比 10% → 100%

| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 10% | 2.111 | **0.100000** | **0.000000** | 0.000000 | 0.055556 | 0.000000 |
| 20% | 4.750 | 0.200000 | 0.000000 | 0.000000 | 0.166667 | 0.000000 |
| 30% | 8.143 | **0.300000** | **0.000000** | 0.000000 | 0.277778 | 0.000000 |
| 40% | 12.667 | 0.400000 | 0.000000 | 0.000000 | 0.388889 | 0.250000 |
| 50% | 19.000 | **0.500000** | **0.000000** | 0.000000 | 0.500000 | 0.500000 |
| 60% | 28.500 | 0.600000 | 0.000000 | 1.000000 | 0.611111 | 0.750000 |
| 70% | 44.333 | 0.700000 | 0.000000 | 1.000000 | 0.722222 | 1.000000 |
| 80% | 76.000 | 0.800000 | 0.000000 | 1.000000 | 0.833333 | 1.000000 |
| 90% | 171.000 | 0.900000 | 0.000000 | 1.000000 | 0.944444 | 1.000000 |
| 100% | 3.403e38 | **1.000000** | **0.000000** | 1.000000 | 1.000000 | 1.000000 |

读法：

* **Mean 严格等于撒谎者的权重占比**，`Mean = s`，斜率 1、截距 0，没有任何缓冲或饱和。
* **Median 十行全是 0.000000**。撒谎者拿走 100% 权重（权重 3.4e38），19 个 0 观点仍是 19 票，中位数纹丝不动。
* **WeightedMedian 在权重严格过半处翻转**：50% 及以下还是 0，60% 起变成 1.0。数学来源：19 个 0 的累计权重 ≥ 一半 ⟺ `19·w_honest ≥ w_liar`。
* **Trimmed 的免疫条件是 `p ≥ 撒谎者权重占比`**：p=0.30 时，占比 ≤30% 的撒谎者被整条裁掉（0.000000）。
* **Trimmed 在占比过半时会帮倒忙**：占比 60% 时 Trim(.05)=0.611111，比不裁的 Mean=0.6 还高。
  数学上：两端等量裁剪后结果为 `(w−pT)/(T−2pT)`，与 `w/T` 比较可得 **当且仅当 w > 诚实总权重（即占比过半）时，裁剪反而抬高结果**。

### 表 2：人头攻击 —— Median 抗的是权重，不是人头

20 个来源、权重全为 1.0，撒谎者从 0 个加到 20 个：

| 撒谎者个数 | Mean | Median | WeightedMedian |
| ---: | ---: | ---: | ---: |
| 1 | 0.0500 | 0.0000 | 0.0000 |
| 5 | 0.2500 | 0.0000 | 0.0000 |
| 9 | 0.4500 | 0.0000 | 0.0000 |
| 10 | 0.5000 | **0.5000** | 0.0000 |
| 11 | 0.5500 | **1.0000** | 1.0000 |
| 15 | 0.7500 | 1.0000 | 1.0000 |
| 20 | 1.0000 | 1.0000 | 1.0000 |

**1 个撒谎者拿 100% 权重也动不了 Median；10 个撒谎者各拿 1/20 权重，Median 立刻变成 0.5。**
Median 把「权重」这个可被操纵的量换成了「人头」，而人头在无成本的 Sybil 场景里同样可以被操纵。

| 360 | 0.031250 | 62.75% | 0.627451 | 0.000000 | 1.000000 |

**拐点有闭式解**：19·d ≥ 1 ⟺ `age ≤ H·log₂(19)` ⟺ H=72 时 **≈ 305.85 小时（12.7 天）**。
也就是说：只要诚实来源普遍陈旧超过 12.7 天，**一个永远新鲜的单点撒谎者就能拿下加权中位数**；
陈旧 20 个半衰期（60 天）后，Mean 已经到 **0.999982**，而 Median 依旧是 0。
这比「权重攻击」现实得多 —— 攻击者只需要保持活跃，等别人掉线。

## 设计取舍

| 取舍 | 选择 | 理由 / 代价 |
| --- | --- | --- |
| 累加精度 | 中间用 f64，出口转 f32 | 几百个来源 f32 连加会积累可见误差；代价是每次都多一次类型转换 |
| 空结果 | 返回 `Option`，不用 0 代替 | 让调用方区分「没取到任何观点」与「观点就是 0」，直接影响 `combine` 里 group=None 的语义 |
| NaN | 一律当 0 / 剔除 | 协议里 0 = 没表态，是最保守的语义；代价是脏数据会被静默吞掉，不上报 |
| 衰减下溢 | 兜底到 `DECAY_FLOOR`（≈1.4e-45） | 满足「永不精确归零」；代价是极端陈旧观点的权重不是 0 而是 1e-45（在 f32 求和里可忽略） |
| 加权中位数 | 累计权重 **≥** 一半即返回（下侧） | 平分时判给数值小的一侧，对攻击者更苛刻：必须**严格过半**才能翻转；代价是 50/50 时结果偏低 |
| 截尾方式 | 按权重轴「切片」，不是整条丢弃 | 权重不等时「裁掉 p 比例权重」的字面含义；代价是边界条目部分计入，`Trimmed(0)` 才精确等于 `Mean` |
| 截尾上限 | `MAX_TRIM = 0.5 − ε/2` | 防止 p=0.5 把权重裁光；代价是占比 >50% 的攻击者 Trimmed 完全无解 |
| 权重过滤 | 四种口径统一剔除 `w ≤ 0` 或非有限项 | 规格的全局前置规则；代价是退化输入（诚实来源权重被压到 0）时 Median 也会丢票 |
| 舍入 | 不做「近似相等」 | 单元测试用 1e-6 容差，集成测试用闭式解/暴力解对拍，避免测试跟着实现跑 |

## 测试

```bash
cd crates/agg
cargo test                 # 60 个测试：40 单元 + 12 对拍 + 8 操纵实验 + 3 doc-test
cargo test --test sybil_report -- --nocapture --test-threads=1   # 看完整表格
```

* `src/lib.rs` 内联单元测试：边界（空/全不合法/NaN/inf/单条）、单调性、clamp、端点精确性。
* `tests/agg_diff.rs`：**独立参照实现对拍** —— 加权中位数用「最小可行阈值」暴力解、截尾均值用分位数黎曼和（20 万步）、`Trimmed(0)≡Mean`、随机数据洗牌不变性、5000 条无漂移。
* `tests/sybil_report.rs`：单点操纵、人头攻击、衰减放大、截尾免疫条件、β 稀释，**每个数字都由断言钉死**。

随机数用自带的 xorshift64（`tests/agg_diff.rs` 内），不引入任何外部 crate。
