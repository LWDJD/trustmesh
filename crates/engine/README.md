# tm_engine —— trustmesh 运行时

把三层拼成一个可用的引擎：`tm_store`（账户表 + 正分清单 + 轮次抽样）、
`tm_view`（定长压缩观点）、`tm_agg`（衰减 + 聚合）。

纯 std，**零外部依赖**，`#![forbid(unsafe_code)]`。不做任何 I/O。

## 三个核心概念

| 概念 | 含义 |
|---|---|
| **正分清单** | 我给谁打过正分。这是**唯一**的信息来源：现在放 0~1 的分数，以后能追踪来源、计权重 |
| **影响力预算** | 一份观点文件的总量恒为 1。我评 3 个人每人 1 分，每人份额 1/3；评 300 个人每人 1 分，每人份额 1/300 |
| **抽样** | 我每轮只取 k 个来源的观点。`(清单长度/k)·轮间隔 ≤ 半衰期/2`，否则衰减变成噪声 |

## 声望公式

~~~text
声望 = β · 个人项 + (1−β) · 群体项

个人项 = 我给他的评分 ÷ 我评过的所有评分之和     （影响力预算）
群体项 = Σ(来源份额 · 衰减 · badlist折扣 · 该来源对我的读数) ÷ Σ(来源份额 · 衰减 · badlist折扣)
~~~

β 默认 **0.3**（作者定：个人 30% + 群体 70%）。

## 快速开始

~~~bash
cd crates/engine && cargo run --example quickstart
~~~

这个例子跑通应用层必须做的五件事：intern → rate → tick → on_view → query。

## 你（应用层）必须负责的事

库**刻意不做**这些，因为它们需要真实世界的语境：

- **网络**：取观点、发观点、重试、超时
- **签名/验签**：库信任 `owner` 参数，不校验它
- **只投递真正的新观点**：重放旧观点会刷新 `last_check`（A8 D4，**未修**）
- **限流 / 防 DDoS / 内容托管**
- **持久化**：引擎状态在内存里，重启即失

## 部署前必读

[../../docs/audit/威胁模型.md](../../docs/audit/威胁模型.md) —— 什么条件下它安全、什么条件下不安全。

最短版本：

| 它防住 | 它防不住 |
|---|---|
| 纯女巫自我吹捧（S1 逐位为 0） | **熟人背叛**：8% 渗透者抬举的同伙能拿 4.37 倍（最坏 8.14 倍） |
| 渗透注入新女巫（S2 越线率 0） | 空账户拿到少量声望（S4，且**清单越长越严重**：m=1000 时 30.4%） |
| 超额声明 / 后登记账户 | 单来源自吹（S5，+83%） |

## 抽样节奏（最容易搞砸的地方）

A10 实测：n=600、k=8、T=30h → 刷新周期 93.75 天，而半衰期 72h ⇒ **90.7% 的来源衰减因子 < 0.1**。

~~~text
硬约束：  (清单长度 / k) · 轮间隔  ≤  半衰期 / 2
        ⟹  k ≥ 2 · 清单长度 · 轮间隔 / 半衰期
~~~

自查用 [`Engine::freshness_stats`]；参数推荐见 [`budget`] 模块。
