## 序列化格式（版本 1，自描述）

~~~text
0     魔数 "TMSNAPSH"（8B）
8     版本号 u32 = 1
12    视图参数指纹 u64（FNV-1a 64 对 buckets/hashers/seed）
20    accounts       u32 n + n × 32B 公钥（下标即编号）
...   ratings        u32 n + n × (u32 编号, u32 评分位模式, u64 last_check, u32 fail_streak)
...   round_members  u32 n + n × u32（本轮全量清单，升序）
...   round          u32 n + n × u32（本轮剩余待抽，顺序即语义）
...   views          u32 n + n × (u32 编号, u32 字节数 L, L 字节, u64 published_at,
                                   u64 last_check, f32×3 噪声底, f32 total_mass, u32 mass_covers)
...   penalties      u32 n + n × (u32 编号, u32 折扣位模式)
...   clock / stat_requests / stat_hits / rng_state   各 u64
末尾  不得有多余字节
~~~

* 浮点一律 `to_bits()/from_bits()` 逐位搬运 —— 「恢复后逐位一致」的关键；
* 空快照固定 **76 字节**（头部 20 + 6 个数组计数 24 + 尾部 32）；
* 版本号写在固定偏移，`EngineSnapshot::version_of(bytes)` 可独立读出；
* 定长 = 可精确算长（`encoded_len()`），无压缩、无变长编码。

## 与任务书结构的两处「必须加」

任务书列出的 `EngineSnapshot` 字段没有下面两项，但缺了就恢复不了：

1. **`round_members`**：`RoundSampler` 有两份状态 —— 本轮剩余 `pending`
   与本轮全量 `members`（本轮抽空后自动重置时用它）。只存 pending，
   恢复后「本轮抽空 → 下一次 draw 自动开新一轮」就没了来源，第二轮抽签立刻分叉。
2. **`view_params_digest`**：**seed 不同时压缩观点的字节长度完全一样**，
   `CompressedView::decode` 只校验长度与桶值有限、会照常解成功。
   于是「参数不匹配」在字节层面**不可见**，恢复出来的引擎会带着桶布局整体错位的
   观点继续跑 —— 比拒绝恢复严重得多。指纹（不可逆、不含配置信息）在这里做早退检查。

## 三层校验（任何一层不过都返回 None，绝不部分恢复）

1. 版本号 = 1；
2. 结构自洽：公钥不重复、ratings/round_members/views/penalties 严格升序、
   round ⊆ round_members 且无重复、评分 ∈ (0, MAX_SCORE]、折扣 ∈ [0,1]、
   噪声底 ≥ 0 且有限、total_mass > 0、mass_covers ≤ 账户数、rng_state ≠ 0；
3. 观点字节能被 `cfg.view_params` 解出来（长度 / 桶布局 / 无 NaN∞）。

`decode` 完全防御性：截断 / 版本不符 / 长度矛盾 / 非有限浮点 / 末尾多余字节
一律 `None`，绝不 panic；数组长度先按「剩余字节 / 单元素最小字节」验算，
伪造 `u32::MAX` 个账户会当场被拒（而不是预分配 128 GiB 被 OOM 杀掉）。

## 使用方式（应用层）

~~~rust
// 存盘
let snap = engine.snapshot(now);          // now = 最近一次 tick/rate 的时刻
let bytes = snap.encode();                // 纯字节，无 I/O
std::fs::write("engine.bin", bytes)?;     // 应用层自己负责 I/O

// 开机
let bytes = std::fs::read("engine.bin")?;
let snap = EngineSnapshot::decode(&bytes).ok_or(Error::Corrupt)?;
let engine = Engine::restore(cfg.clone(), snap).ok_or(Error::ConfigMismatch)?;
// 之后 query / tick / export_view 与关机前逐位一致
~~~

## 已知边界

* **快照不含 cfg**：调用方必须自己保管并原样传入 `new` / `restore`；
  参数不符会被拒（含空观点缓存的快照 —— 它记录的是「按哪套参数拍的」）。
* **clock 会被改写成导出时刻**：`report_bad_account` 的时间基准是「最近一次带
  时间参数的调用」，导出时传进来的 `now` 就是它。不在快照里存一个与所有
  可观测量都对不上的时刻。
* **「语义上合法但与原件不同」的破坏不会被拒**：账户表里换掉一个公钥、
  观点桶值里改一位尾数，解出来仍是自洽状态（它只是**另一种**状态）。
  检测「字节被替换」属于完整性校验（哈希/签名），不在本格式职责内 ——
  应用层若要防篡改，应在文件外层加摘要。
* **不压缩**：格式刻意保持定长、零依赖、可算长度。需要省体积时应在应用层套
  压缩（快照是纯字节，压缩前后都不影响逐位恢复）。
* **抽样流种子仍由调用方给**：`restore` 精确恢复的是**流的位置**（state），
  不是种子；不同节点仍应各自 `with_seed` 起手，之后用快照接力。
