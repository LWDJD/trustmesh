# `tm_mincore` 接入协议（应用层要做什么）

> 对应实现：`crates/mincore`（744 行生产代码，只用 `std`，零外部依赖）。
> 对照 `tm_engine` 的协议见 [`../engine/PROTOCOL.md`](../engine/PROTOCOL.md)。
>
> **本文只讲「应用层必须做什么」。** 内核自己保证什么、不保证什么，§0 有清单。

## 0. 内核保证什么 / 不保证什么

### 0.1 内核保证（结构性的，不依赖调用方守规矩）

| 性质 | 怎么保证的 |
|---|---|
| **单来源预算恒为 1** | 归一化是「先夹后除」：`q ∈ [0,65535]` 定点，`v = q/Σq`，Σ 是精确整数和 |
| **女巫拿不到声望** | 定长表里没有哈希碰撞 ⟹ 没有噪声底 ⟹ 没被背书过的账户读数是**精确 0** |
| **空账户精确 0** | 同上（不是「接近 0」） |
| **逐位可复现** | 全部计算是确定性整数/f64；同一输入 ⟹ 同一 f32 位模式（wasm 与 native 已验证相同） |
| **解码不 panic** | 任何畸形字节返回 `None`，绝不 panic、绝不按畸形长度预分配 |
| **衰减只改相对权重** | `0.5^(Δt/half_life)` 乘在每个来源的权重上，归一化后整体不变 |

### 0.2 内核**不**保证（必须应用层做）

| 缺口 | 后果 | 谁来做 |
|---|---|---|
| **账户号 ↔ 公钥的映射** | `Acc` 是不透明的 `u32`，内核不验签名 | **应用层**：账户号必须由公钥可验证地派生 |
| **视图真的来自那个账户** | `on_view(owner, view, ...)` 的 `owner` 是**调用方说的** | **应用层**：必须验签 |
| **抽取谁的观点** | `tick()` 只给「我这轮该问谁」，不负责真的去问 | **应用层**：投递、超时、重试 |
| **发现哪些节点** | 内核完全不管 | **应用层**：见 §0.5 |
| **防 DDoS / 防淹没** | 明确不承诺 | **应用层** |
| **内容排序 / 推荐** | 明确不做 | **应用层** |

## 0.5 传输层被劫持时（eclipse）应用层必须做什么

> 结论从 `tm_engine` 那边搬来，威胁模型完全一样。实测见 [`../../docs/audit/传输淹没.md`](../../docs/audit/传输淹没.md)。

### 0.5.1 攻击者能伪造什么、伪造不了什么

| 攻击者能 | 攻击者不能 |
|---|---|
| 让你**看不到**某些节点（淹没） | 伪造一份**你没评过的人**的视图并通过 `on_view`（结构性拒绝） |
| 冒充**你的朋友**给你发视图（如果你不验签） | 让女巫拿到声望（没有背书路径） |
| 篡改你收到的字节（如果你不验签） | 让单来源预算超过 1 |
| 重放旧视图（**能**刷新鲜度，见 D4） | 让你的 `Σv` 不等于 1 |

### 0.5.2 三条硬要求

1. **发现必须从「我自己的清单」出发**，不能从「别人给我的名单」出发。
   内核的 `Node::claims()` 就是这份清单：`tick()` 只会从中抽人。
   **如果你用别人给的名单去发现节点，攻击者就能把你隔离。**

2. **必须验签。** `on_view(owner, view, published_at, now)` 三个参数里，
   `owner` 和 `published_at` 都是**调用方声称**的，内核一律不信。
   应用层必须验证：`view` 字节确实由 `owner` 的私钥签过，且时间戳在合理窗口内。

3. **必须多路径尝试。** 一个节点拿不到就换传输通道。
   内核的 `probe()` 是兜底：它从**整份清单**抽，比 `tick()` 更广，
   用于「连续失败」的节点 —— 但**它不负责重试**，重试是应用层的事。

### 0.5.3 用错的方式（会静默失效）

~~~rust
// 错：从「别人给我的节点列表」建清单
for p in remote_peer_list { node.rate(p.acc, 0.5, now); }
// 攻击者只要控制那份列表，就能决定你能看到谁。

// 错：不验签就 on_view
node.on_view(claimed_owner, decoded_view, 0, now);  // claimed_owner 可以随便填
// 后果：任何人可以冒充你最好的朋友，把女巫塞进你的分布。
~~~

## 1. 每轮要做的四步

~~~text
1 发布  publish(now) -> SparseView -> encode() -> 签名 -> 广播/存到可拉取处
2 抽取  tick(k) -> Vec<Acc>（本轮该问谁，不重复、抽完自动开新一轮）
3 投递  on_view(owner, view, published_at, now) -> bool
4 兜底  probe() -> Vec<Acc>（对连续失败的节点做更广的抽样）
~~~

### 1 发布

~~~rust
let view = node.publish(now);        // SparseView，已按 cap 截断
let bytes = view.encode();           // 恰好 cap*6+2 字节
let signed = sign(&bytes);           // 应用层：签名
broadcast_or_store(signed);
~~~

**频率建议**：每轮一次，不要更频繁（发布是 `O(视图数 × cap + 清单长度)`，见性能基准）。

### 2 抽取

~~~rust
let who = node.tick(k);              // 一轮内不放回；抽完自动开新一轮
// 应用层：对每个 who 发请求拿它的视图
~~~

`k` 超过本轮剩余时只返回剩余的；`k == 0` 是纯查询（不 sync、不 reset、不吃随机数）。

### 3 投递

~~~rust
// 应用层：验签 + 解出视图
let view = SparseView::decode(&verified_bytes, cap)?;   // 或 decode_prefixed
let accepted = node.on_view(owner, view, published_at, now);
if !accepted { node.on_view_failed(owner); }   // 记账（不影响抽样）
~~~

**两种拒绝是结构性的**：owner 不在我的清单 / 视图 `total_q == 0`。

### 4 兜底

~~~rust
let extra = node.probe();   // 从整份清单抽（比 tick 更广）
~~~

**只对「连续失败」的节点用**：`on_view_failed(owner)` 让 `fail_streak` +1，
但**不影响抽样**（内核刻意砍掉退避 —— 退避会让攻击者能靠「故意失败」控制你的抽样顺序）。

## 2. 持久化

**关机前必须做**，否则重启后节点会在**下一步就分叉**。

快照包含：正分清单、观点缓存、抽样位图、随机流状态、统计计数。
（`src/snapshot.rs` 正在补齐中，补完后本节会更新为具体的 `Node::snapshot()` / `Node::restore()` 用法。）

## 3. 声望查询与消费

| API | 代价 | 用途 |
|---|---|---|
| `query(acc, now)` | `O(来源数 · log cap)` | 关心单个账户时用（**不要**为「我不关心的账户」付钱） |
| `distribution(now)` | `O(视图数 · cap + 清单长度)` | 需要整份分布时用（排序、批量判定） |

两者在同状态下**逐位一致**：`query(acc,now)` 恰等于 `distribution(now).get(acc)`（有测试守着）。

**读数的含义**：`[0, 1]` 内的相对声望，`distribution` 的 Σ ≡ 1。
它**不是**绝对分，只用于**同一节点内的相对排序**。
**不同节点的读数不能直接比较**（各人的清单与视图不同）。

## 4. 部署检查清单

| # | 检查 | 为什么 |
|---|---|---|
| 1 | **`cap` 全网一致** | 格式不自描述 cap ⟹ 不一致时整条视图被拒 ⟹ **网络分裂成孤岛** |
| 2 | 每节点 `cap >= 你的关注上限` | 否则截断丢质量（cap=128 时 20.1% 视图被截、平均丢 2.81%） |
| 3 | 账户号由公钥可验证地派生 | 否则谁都能冒充 |
| 4 | 收视图时**验签** | `on_view` 不信 `owner` |
| 5 | 发现**从自己的清单**出发 | 否则可被 eclipse |
| 6 | 关机前**存快照** | 否则重启后分叉 |
| 7 | 明确 `half_life` | 它决定「伤害时效」（默认 72h） |
| 8 | 明确 β | 它决定「熟人背叛 vs 陌生人刷分」的权衡（默认 0.3） |

完整威胁模型见 [`../../docs/audit/威胁模型.md`](../../docs/audit/威胁模型.md)；
cap 取值实测见 [`../../docs/audit/cap决策.md`](../../docs/audit/cap决策.md)。

## 5. 最小可运行参考

见 `examples/quickstart.rs`（两节点互评 + 查声望的完整流程）。跑：`cargo run --release --example quickstart`。

它演示了三个最容易踩的前提：
1. **`on_view` 要求「我已给 owner 打过分」** —— 没打过分的来源，内核直接拒收（结构性）；
2. `publish()` 返回 `SparseView` 不是字节，要自己 `.encode()`；
3. `decode` 需要 `cap`（或用带前缀的 `decode_prefixed`，如果那个 API 已补齐）。
