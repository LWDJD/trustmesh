## 目录结构

```text
docs/
  索引.md          机制索引 + 文件全表 + 数字索引（找东西用）
  交接文档.md       规则与现状（接手的人先读这个）
  README.md        本文件
  audit/           审计报告 43 份 .md + 11 份原始数据（A1~A13 / B0~B2 / C1~C2 / P0~P3 + 专题）
  experiments/     实验报告 10 份（D1~D4 / L1~L5）
  planning/        计划与蓝本（4 份）
  raw-output/      实验原始输出（14 份 .txt/.log，是实验报告的证据）
```

### `audit/`（43 份 .md + 11 份原始数据）

| 系列 | 是什么 |
|---|---|
| `A1`~`A13` | 逐模块审计（engine / store / view / decay / group / ablation / debt / attack / fidelity / sampling / scale / kernel / spec） |
| `B0`~`B2` | 基线与判据（badlist 分母） |
| `C1`~`C2` | badlist 仿真与报告机制 |
| `P0`~`P3` | 边界问题修复与衰减目的 |
| 专题 | 威胁模型 / 无限规模 / 有损压缩架构 / 传输淹没 / 工程可用性评估 / 耦合度评估 / 历史遗留盘查 / 单crate重构方案 / mincore 系列 |

### `experiments/`（10 份）

D1~D4（衰减相关）、L1~L5（潜伏相关）+ 实验报告总览。

**注意**：这些报告里有一部分数字基于**旧口径**（分母只算有观点的来源那一版）。
方向结论仍然可信，**具体数字不可用** —— 见 [交接文档.md](交接文档.md) §7.7。

### `planning/`（4 份）

两级衰减实验计划、验收测试蓝本、潜伏仿真设计、待实测清单。

**这些是当时的计划，不是现状。** 现状看 [交接文档.md](交接文档.md) §7。

### `raw-output/`（14 份）

实验报告引用的原始输出。**不要直接读**（很长），报告里已经提炼过了。

## 三条规矩

1. **入口在根目录，不在这里。** 新人应该从 `../README.md` 开始。
2. **历史档案不改。** `audit/` 与 `experiments/` 里的数字是当时的事实，
   即使现在看是错的也不要回改（会变成伪造历史）。要纠正就在新文档里写「某某报告的数字已被 X 取代」。
3. **`../设计意图.md` 与 `../设计规格.md` 永远不改。** 前者是作者原话，
   后者需要作者点头才能改（目前有 8 处与代码不一致，已记录在交接文档里，等作者决定）。
