# A1 — crates/engine 数值与不变量审计

> 分支 `audit/a1-engine` · 工作树 `wt/a1_engine` · 只读审计：**没有改动 crates/engine/src/lib.rs 的任何一行**，
> `EngineConfig::default()` 逐位不变（由 `default_config_fields_are_unchanged` 钉住）。
> 所有数字来自 `crates/engine/src/bin/audit_a1.rs` 的输出，原文落在 `审计/a1_out/*.txt`。

## 0. 一句话结论

engine 的**浮点卫生是干净的**（2000 个随机场景 0 次 NaN/越界、0 次乱序敏感、0 次 panic 路径），
坏的是一处**归一化口径**：群体项的分母只含「已缓存的那些观点」，不含「我评过但还没取到的来源」。
于是「1/N 影响力预算」在覆盖不全时变成「1/M」，**冷启动期 1 份观点就能决定 70% 的信任**（N=101 时是诚实账户的 236.7 倍）；
同时个人项（上限 1/N）与群体项（上限 1）不同尺度，使 **S3 / S4 在 β=0.3 下结构上不可能通过**——
S4 的未评分账户可以拿到「我评分 + 全网推荐」账户的 **99.58%**。
这不是浮点误差能解释的量级，改精度没用，必须改分母口径。

## 1. 结论（每条都可追到命令 + seed + 样本量）

1. **归一化**：2000 个随机场景（11 维随机配置 × 随机输入 × 4 次重建），非空分布 1765 个，
   `|Σ−1|` 均值 **4.688e-8 ± 4.518e-8**、最大 **3.302e-7**；**91.3% 的场景 > 1e-9**、**0 个 ≥ 1e-6**。
   任务要求的「误差 < 1e-9」在 f32 输出下不可达（N=3 就已 2.98e-8，N=5000 达 2.37e-5）。
   空分布 235 个（无评分 / β=0 且群体项为 0），此时总和 = 0，不是 1 也不是 NaN。
2. **取值域**：越界 0 次、NaN/Inf 0 次。含恶意输入：6×3.4e38 累加成的 inf 桶、NaN 分数、全零视图、时钟回拨。
3. **个人项**：未评分账户 10284 个样本，query **逐位等于 +0.0**，0 例外；β=1 时 Σquery=1（1977/1977 个「至少有一条评分」的场景）。
4. **确定性**：同输入两次重建 **2000/2000 逐位相同**；on_view 乱序投递 **2000/2000 逐位相同**；
   重复覆盖「先 A 后 B」与「只投 B」**2000/2000 逐位相同**。
   但重排 **intern 顺序**后 86/200（43.0%）场景最后一位不同，最大逐元素差 **1.19e-7**（`total_mass`/`total_rating` 是 f32 按编号顺序累加）。
5. **极端输入全部安全**：正分清单为空 → 空分布（和 0）、query=0、coverage=0、无 NaN；
   唯一评分 1e9(MAX_SCORE) → share=1.0、query=0.3、分布 [1.0]；全零观点与「没有观点」**逐位相同**；
   β=1 与「没有观点」**逐位相同**；β=0 且无观点 → 空分布；β=0 且有观点 → 分布 [1.0]。
6. **衰减因子**：dt=0→1.0、72→0.5、1e6→**1.401e-45**(DECAY_FLOOR)，**永不 >1**（回拨也不 >1）。
   但回拨把「1e6 小时前的来源」从 1.401e-45 恢复到 1.0（**7.136e44 倍**），在 2 源场景里直接把群体项从 1.0 改成 0.5。
7. **冷启动**：0 观点时 query=β×个人项，再归一化后 **β 被完全消掉**（β∈{0.15,0.3,0.7,1} 与 1/101 的最大差 ≤2.95e-9）；
   `s=0`（coverage=0）与 `s=1` 在该点**逐位相同**——第二层衰减在「一份观点都没有」时是**空操作**，
   因为 `aggregate(∅)=None` 早就把群体项置空了。真正的冷启动缺陷是**第一份观点到达时的跳变**：L1 = **1.386**（最大可能 2）。
8. **S3 结构式**（实测吻合到 1e-6）：`D[T] = β/N + (1−β)·m/M`（M=已缓存观点数，m=其中推荐 T 的份数）。
   M=1 → **0.702972**（诚实账户 0.002970 的 **236.67 倍**）；M=2/5/10/50/100 → 118.8/48.1/24.6/5.7/**3.36 倍**。
   M=N 时倍数 = `1+(1−β)/β = 3.33`，**与 N 无关**——所以项目实测的 2.29 倍不是偶然，是 β=0.3 的算术必然。
9. **S4**：完全空账户 0.000000；未评分但被 100 个来源一致推荐 **0.699999**；我评 1.0 无人推荐 0.002970；
   我评 1.0 且被一致推荐 0.702972 ⇒ **未评分账户 = 后者的 99.58%**，是「只评分不推荐」的 **235.7 倍**。
10. **S5**：同一份「我只给 T 我 0.1% 的信任」，被推荐账户 U 已登记时 v(T)=**0.001000**、D[T]=0.003670；
    U 未登记时 v(T)=**1.000000**、D[T]=0.702972。**1000 倍 v、192 倍 D**，与 T 无关、只与接收方的账户表有关。
11. **资源**：单份观点 40960 B；缓存 1000 份实测 RSS 从 **4.5 MiB → 43.9 MiB**（+39.4 MiB），10 万份 ≈ **3.8 GiB**，
   无上限配置项、唯一清理入口是手动 `prune_stale`。`on_view` 线性于 N（N=8000 时 **2482.8 µs/次**）；
    `trust_distribution` 是 O(N·V)：N=V=4000 时 **20.6 s/次**（4 次独立运行 17.1–26.1 s），每翻倍 ×4.0–5.0；按此外推 16632 账户 ≈ **6 min/次**（按 N² 外推，未实测）。
12. **代码审查**：query / on_view / trust_distribution 路径**没有 unwrap / expect / panic / 除零 / 下标越界 / 整数溢出**
    （唯一 panic 是 `AccountTable::intern` 在 u32::MAX，文档已声明、不可达）。有 3 处**静默降级**（见 D6/D9），
    2 处**静默失效**（`decay_floor=∞` 让整个群体项消失；未评分来源的观点永久占 40 KiB 且永不参与）。

噪声底：写入 1/10/100/1000/2048/4096 条，`noise.median` 全为 **0.000000**（p95 最大 0.001），
默认 `noise_multiplier=1.0` 下过滤条件 `v < 0` **永不成立**——这道门槛在默认配置里是空转的。

退避：连败 64 次的来源在本轮第 **100/100** 次 tick(k=1) 才被抽到，但**每轮仍被抽 1 次**；
即退避只改「本轮内的顺序」，不改「每轮抽几次」，文档里「少占带宽」只在应用不把本轮抽空时成立。

- `s=0` 与 `s=1` 在 m=0 时**逐位相同**（`dist_bits` 相等）⇒ 4.9 节机制在冷启动点是空操作。

## 3. 复现命令

环境：Windows + PowerShell，**必须** `-j 1`（并行 link 在本沙箱会 LNK1104 打不开 .tmp 链接文件）。

```powershell
cd crates/engine
$env:TMP="$PWD\.tmp"; $env:TEMP="$PWD\.tmp"

# 全量测试：88 passed / 6 ignored
cargo test -j 1

# 被记录下来的缺陷（断言「缺陷仍在」，因此也是绿的）
cargo test -j 1 --test audit_a1 -- --ignored --nocapture

# 全部审计段（约 92 s）
cargo run --release --bin audit_a1 -- all ../../审计/a1_out

# 分段（各自的耗时/样本量；共享机器，wall-clock 抖动约 1.5×）
cargo run --release --bin audit_a1 -- inv   ../../审计/a1_out   # 2000 场景，43.8 s
cargo run --release --bin audit_a1 -- ext   ../../审计/a1_out   # 极端输入
cargo run --release --bin audit_a1 -- cold  ../../审计/a1_out   # m=0..100 冷启动
cargo run --release --bin audit_a1 -- float ../../审计/a1_out   # N=3..5000
cargo run --release --bin audit_a1 -- res   ../../审计/a1_out   # N=500..8000，约 40 s
cargo run --release --bin audit_a1 -- s34   ../../审计/a1_out   # S3/S4/预算

# 实测常驻内存（1000 份缓存观点，采样点 2.5 s）
$env:A1_VIEWS="0";    .\target\release\audit_a1.exe mem   # WorkingSet 4.5 MiB
$env:A1_VIEWS="1000"; .\target\release\audit_a1.exe mem   # WorkingSet 43.9 MiB
```

随机源与样本量：`inv` 的主随机源是 splitmix64，seed=`0x00A10001`，2000 个场景 × 每场景 4 次重建
（原样、重建、乱序、覆盖），约 1.2 万个引擎实例；`float` 4.2/4.3 分别 50/100 组 × 1000 项；4.4 是 200 个场景 × 2 种 intern 顺序；
`res` 每档 5 批 × 20 次取最小批均值；`cold` 是 8 个 m 值 + 2 套配置。没有裁剪 seed 数，也没有估算任何数字。

## 4. 缺陷清单

| 编号 | 严重度 | 症状（实测） | 最小复现 | 影响 S | 建议 |
| --- | --- | --- | --- | --- | --- |
| **D1** | 低 | `trust_distribution` 总和只有 f32 精度：N=3 起 2.98e-8，N=5000 达 2.37e-5；任务要求 1e-9 | `float` 4.1；`defect_sum_to_one_1e9_is_unreachable` | S6 | 输出改 f64 或做一次 Kahan 归一化；否则把契约写成 1e-5 |
| **D2** | **严重** | 群体项分母只含「已缓存观点」⇒ 1 份观点 = 100% 群体意见：D[T]=0.703，是诚实的 **236.7 倍**；M=N 时仍有 **3.36 倍**（=1+(1−β)/β，与 N 无关） | `cold` m=1..100；`defect_one_view_controls_the_whole_group` | **S2、S3** | **改**：分母计入全部已评分来源的权重（缺失观点按 0 计，等价 `s=coverage`）。实测可把 m=1 从 0.703 压到 **0.0323**（21.8×） |
| **D3** | **严重** | 个人项上限 1/N、群体项上限 1，两者不同尺度 ⇒ 未评分账户可达「评分+一致推荐」账户的 **99.58%**；比「只评分不推荐」高 **235.7 倍** | `s34` 6.1；`defect_unrated_account_matches_rated_one` | **S4（从未测过，现在有数了）** | **改模型**：group 必须与「目标本身是否在我的清单里 / 我对它的个人项」耦合，或让 personal 与 group 同尺度；纯数值修不了 |

## 5. 建议：删 / 改 / 留

**改（按优先级）**
1. **群体项分母**（D2/D3）：把「已评分但未取到观点」的来源按权重 0 计入分母（= 让 coverage 进分母）。
   已用同一份输入做过反事实：m=1 时 D[T] 0.703 → **0.0323**，S3 倍数 236.7 → 10.9。这是唯一能把 S3 从「结构必败」拉回「可调」的改动。
2. **total_mass 语义**（D4）：改成发布侧总量恒 1（v=query，不除 total_mass），否则 S5 的 1000 倍放大无解。
3. **默认打开覆盖率**（D2/D13）：`unreachable_after>0` 且 `remove_when_coverage>0` 时 s 才生效，
   而默认两者都是 0 ⇒ 4.9 节的整套机制在默认配置下贡献为 0。要它贡献，就得改默认——这会违反「默认逐位不变」，
   所以是**产品决策**，不是审计能替做的。
4. 资源（D7）：`trust_distribution` 的 O(N·V) 与 40 KiB/份的 views 缓存，在 16632 账户规模下不可用。
5. 小修：D5（单调时钟）、D6（θ 短路）、D9（clamp floor）、D8（rate 校验）、D11（f64 累加）。

**删**
- `published_at` 字段（存了从不参与计算，是纯粹的误导：真正的衰减基准是 `last_check`）。
- 噪声底门槛（D12）：默认配置下 median=0，`v<floor` 永不成立；要么删，要么改成 p95 并证明它挡掉了什么。
- `decay_floor`（如果保留，必须 clamp 到 [0,1]）：它只改「来源之间的相对新鲜度」，
  而群体项本身对均匀缩放免疫——对反女巫没有可测贡献。

**留**
- `s` 的覆盖率项（D2 的现成解药）、`min_group_sources` 门槛、`prune_stale`、BTreeMap 保证的遍历顺序、
  `elapsed()` 的 saturating_sub（回拨不 panic、不产生负年龄）、`combine` 的 NaN→0 夹紧。
- `on_view` 的「成功才刷新 last_check」分离（失败不变旧）——这条是正确的，且已被现有测试钉住。
