# A2 — crates/store 抽样正确性与均匀性审计

- 审计对象：`crates/store`（tm_store 0.1.0，1879 行 lib.rs / 3 个测试文件）
- 分支：`audit/a2-store`
- 支撑程序：`crates/store/src/bin/a2_audit.rs`（A2 全部实验，确定性可复现）
- 回归锁：`crates/store/tests/audit_a2.rs`（17 个绿灯 + 4 个 #[ignore] 记录缺陷）
- 原始输出：`审计/A2-store.raw.txt`（程序 stdout 全文，未编辑）

全部实验固定 seed、固定样本量，**无估计值、无抽样了事**。单次运行总耗时 1.66 s（release）。

---

## 0. 结论

1. **均匀性通过**。9 个卡方格（n=2/5/50 × k=1/2/5，各 10 万次独立试验）中，6 个有信息量的格子 χ² 全部落在拒绝域之外（最小 p = 0.3759，n=50/k=1 的 χ²=34.991、df=49、p=0.9344）；最大偏差 4.35%（n=50,k=1）。另外 3 个格子（k≥n）每次试验必然覆盖全员，χ²≡0，**无信息量**。
2. **轮次位图边界正确**。k>n 一律返回 n 个、不重复、不 panic（含 k=usize::MAX、n=0）；10000 轮 × n 次 draw(1) 后每项恰好 10000 次、轮内重复 0、每轮恰好覆盖全员。唯一的形态问题是**轮尾不足 k**：n=50/k=7 时每轮浪费 6 个名额（10.71%），n=2/k=5 时浪费 60%。
3. **退避不会死循环 / 除零 / 少抽**。全部 streak=200、65、64、100000 的 20 组组合全部抽满；n=1..64 × k∈{1..n, n+1, 2n, usize::MAX} × 3 种 streak 分布共 **6816 组合 0 失败**，最慢单次 15 µs；1000 轮歪斜 streak 下轮内重复 0、覆盖 0 缺失。
4. **但退避对「每轮抽查次数」的影响严格为 0**：一轮不放回 ⇒ 每个条目每轮恰好被抽 1 次。实测 3 个 seed × 200 轮，攻击者/诚实双方各 20000 次，份额 50.0000%，每人每轮 1.0000 次。退避**只改变轮内顺序**：攻击者平均排位 87.07，诚实 113.93（均匀抽样是 100.88 / 100.12）。
5. **这个相位偏置在截断窗口里就是真实多抽**：轮首前 1 个 tick 攻击者份额 64.05%±14.02%（公平 50%，+14.05 个百分点），前 10 个 tick（半轮）58.78%±3.53%（+8.78）；到完整一轮回到 50.00%±0.00%。启动 / `restart_round()` / 停机重启后的第一批抽样正好落在这个窗口里。
6. **PositiveList 状态机 20/20 通过**。反女巫关键项成立：`record_failure` **不**刷新 last_check（50 次失败后仍是 1000）；`record_success` 清零连败并刷新时间；NaN / 负数 / -0.0 一律当删除；MAX_SCORE 与 +∞ 截断到 1e9。
7. **share/shares 的「总和恒为 1」是近似**：随机评分下最大偏差 7.1 ULP（8.5e-7，n=1000）；1000 条全 MAX_SCORE 时偏差 **79.7 ULP（9.5e-6）**，total() 从 1e12 漂到 1.0000095e12。极端比值（MIN_POSITIVE vs 1e9）下正分条目的份额**下溢为 0.0**。
8. **现有均匀性测试零检出力**（仓库证据链的漏洞）：把抽样换成"零随机的升序枚举"（draw_all）甚至"1.0 分永远排第一的确定性顺序"，同一套 1000 轮统计仍然 1000..1000、χ²=0、p=1.0000。用它证明"抽样不看评分"是循环论证。
9. **`share()` 是 O(n) 重算**（每次重算 total()），`Engine::query` 每账户调一次 ⇒ trust_distribution 是 O(n²)：n=16632 时逐个 share 花 **580.7 ms**，比一次性 `shares()` 慢 **3972 倍**。

## 5. 建议：删 / 改 / 留

### 留（反女巫有效，不要动）
- `RoundSampler` 的轮次位图 + `swap_remove`：均匀（χ² 全部通过）、不放回（0 重复）、无 panic（6816 组合）、轮次精确覆盖（10000 轮 0 偏差）。这是"攻击者买不到额外曝光"的结构性保证。
- `PositiveList::record_failure` **不**刷新 last_check：反女巫关键不变量，实测 50 次失败后时间戳不动。
- `record_success` 唯一清零连败：实测成立。
- `Rng::next_below` 的拒绝采样：取模偏差为 0。

### 改（按优先级）
1. **删掉或重做 `draw_backoff` 的加权选择**（D1）。它对每轮次数贡献为 0（实测 50.0000% / 1.0000 次每轮），却贡献了轮首 +14.05 pp 的相位偏置和 O(k·n) 复杂度。若只是想"少打扰离线源"，正确形态是**每轮随机打乱 + 轮内不排序**，而不是按 2^-streak 排序；若保留权重，至少要在轮首对"连续成功者"降权，把权重与"在线时长"解耦。
2. **消除 `share()` 的 O(n) 重算**（D2）：缓存 total 或强制走 `shares()`。16632 账户下单次 trust_distribution 580 ms 会直接限制 S2/S3 实验规模。
3. **`total()` 改 f64 累加**（D4），或在 `shares()` 里做一次 Kahan 补偿；否则"总和恒为 1"在千条高评分时偏差 9.5e-6。
4. **份额下溢保护**（D3）：`s/total` 用 f64 计算后再转 f32，或对正分条目给一个 f32::MIN_POSITIVE 的下限，避免"正分但权重 0"。
5. **修注释**（D5）：把 lib.rs:213-215 与 lib.rs:22 的 "(0,1]" 改成 "(0, MAX_SCORE]"，并把"截断为 1.0"改成"截断为 MAX_SCORE"。
6. **重写均匀性测试**（D6）：用"每次 reset 后只抽 1 个"的首抽分布（本报告 E1a/E1c 的形式），才能测出"按评分加权"；现在的每轮计数法对任何"每轮覆盖全员"的实现在数学上必然通过。
7. 批量抽取补一个"跨轮补满 k"的可选接口（D7），或在文档里明确"轮尾会返回不足 k，调用方不要用它计算每轮问询预算"。

### 删（候选）
- 存储层没有可以整块删掉的结构；**唯一值得考虑删除的是 `draw_backoff` 的权重排序**（不是整个函数）：保留"跳过已知死源"的价值可以用更简单的方式实现，而它目前的净反女巫贡献为 0，截断窗口贡献为负（+8.78~+14.05 pp 给攻击者）。

## 6. 代码审查补充（无实测数字，均为静态结论）

- `pick_weighted` 的浮点回退分支（`target >= acc` 时返回 `last_positive`）理论上可达：`next_unit * total` 在 total 较大时可能舍入到恰好 total。概率约 1e-16 量级，偏差方向是"最后一个候选"，可忽略但存在。
- `draw_backoff` 里 `streaks` 与 `pending` 用同一套 `swap_remove(j)` 保持一一对应，正确。
- `ensure_round` 是三个抽取入口唯一的"自动开新一轮"实现，无重复代码导致的状态分叉。
- `sync` 只做保留/剔除、不把新成员塞进本轮，保证"一轮内不重复"，正确。
- `normalize` 的去重 + 升序不改变均匀性（下标由 next_below 均匀产生），正确。
- `is_live` 的 `saturating_sub` 让时间回拨按 age=0 处理（更 live），与文档一致。
