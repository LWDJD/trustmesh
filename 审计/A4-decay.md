# A4 · 衰减机制对「反女巫」到底贡献了什么（消融实验）

> 分支 **audit/a4-decay** · 实验代码 crates/exp/src/bin/a4_ablation.rs ·
> 汇总脚本 审计/a4_stats.py · 机器生成的完整表 审计/a4_tables.md · 原始数据 审计/数据/
> 全部 S 判据数字来自**真 runtime**（tm_engine::Engine 的 rate / tick / on_view /
> query / trust_distribution / export_view），**没有一条**来自集中式近似
> tm_exp::run_case_full（它只出现在第 6 节的「口径对照」里）。

## 0. 一句话结论

**衰减对 S1/S2/S4/S6 的净贡献 ≤ 4%（CI 全部跨 0），对 S3 只有背书场景达到 6.3%（72h）/ 10.4%（24h），
对 S5 反而恶化 60~240%（单来源上限 1.60× / 3.40×）。它唯一的一阶效应是「遗忘」：
把攻击残余从关掉时的 99.0% 压到 72h 的 25.0%（−74.7%，95% CI [−0.83, −0.65]）、24h 的 −4.3%（相对 off −104%）。**
因此「衰减对反女巫贡献 < 5% ⇒ 可以删」这个推理**基本成立（只有 S3 背书一条例外）**，
但删除要付出「攻击结束后 600h 仍保留 99% 伤害」的代价——这个代价不在 S1~S6 里。

## 1. 实验设计（一句话版）

| 项 | 取值 |
|---|---|
| 底座 | L3/D1/D4 的多 runtime 模板：300 人、10 轮观点交换、每轮 30h、每轮抽样 12 |
| 离线 | dormancy 逐 seed 二分标定到末轮离线 ≈ 60%（主表）；另跑 90% 复现 D3 |
| 场景 A（S1/S2/S4/S3a/Spearman） | 3 个潜伏者 + 每个引入 20 个女巫（共 60 个注入），潜伏者给收益方 1.0 |
| 场景 B/C（S3） | 渗透 10%（30 个被收买）/ 背书 20%（60 个背书者） |
| 场景 D（攻击残余） | 600h、30 轮；t=120 注入载荷、t=300 攻击者转离线，只剩缓存副本 |
| 空账户 | 每台引擎 intern 48 个从未被评分、也从未出现在任何观点里的账户 |
| 消融矩阵 | decay_enabled ∈ {true,false} × half_life ∈ {24,72,168,720} |
| 样本量 | 矩阵 / S3：**16 个 seed**（11,23,…,251）；残余：**8 个 seed**（11,…,131） |
| 统计 | 同 seed 配对差；95% CI 用 t 分布（df=n−1）；离散度一律给样本标准差 |

**矩阵的 8 个格子 → 5 个互异配置。** decay_enabled=false 时半衰期不参与任何计算，
所以 off24/off72/off168/off720 是同一个配置：子命令 det 用 f64 位模式哈希验证四者**逐位相同**
（OFFH_IDENTICAL=1）。主表因此只跑 5 列，另 3 个 off 格子由等价性覆盖。

**攻击落地。** 世界自然产生的「攻击者→收益方=1.0」可能根本没发生（潜伏者先休眠就永远轮不到它打分；
diag：infil seed=37 的自然落地数 = 0/30）。为保证所有配置测的是同一个「攻击已落地」的世界，
对没有给收益方打过分的攻击者补一条 1.0（与 L3 对女巫的注入口径一致）。这不是伪造优势：
它只让 S3 的分子在 5 个配置间可比；绝对值与历史 2.29 / 1.97 不可直接比较（场景参数不同，见 6.3）。

### 2.7 S6 · 确定性

## 3. 三个必答问题

### Q1 关掉衰减，S1 / S2 / S3 分别是变好、变差、还是不变？

### Q2 半衰期从 72h 改到别的值，反女巫指标有没有单调关系？

**有，但分指标**：

- S1：**单调**。H=24 → 720 时女巫可见度从 0.02841 降到 0.02741（−3.5%），13/16 个 seed 严格单调。
- S3 潜伏者：**单调**。0.12286（24h）→ 0.12696（720h），16/16 个 seed 严格单调，幅度 −3.2%。
- S3 渗透 / 背书：**单调**。渗透 6.72→6.32（−6.1%）；背书 12.60→11.29（−10.4%）。
- 攻击残余：**单调且最强**。0.9898（off）→ 0.9050（720h）→ 0.6142（168h）→ 0.2502（72h）→ −0.0429（24h）。
- S5 单来源上限：**单调但方向相反**。1.00（off）→ 1.05（720h）→ 1.23（168h）→ 1.60（72h）→ 3.40（24h）。
- S2 / S4 / S6：**不存在单调关系**（恒为 0 / 恒相同）。
- Spearman：**不单调**。72h 最高（0.4489），24h 最低（0.4276），比 720h（0.4359）还低。

**结论：H 越小，女巫/收益方越可见度越低（好），但单来源套利越强（坏）、排序质量在 72h 最好。
不存在「H 越小反女巫越好」这种单向关系。**

### Q3 「如果衰减对反女巫只贡献 < 5% 的改善，建议删除是否成立？」

**前提核对（16 seed）**：

| 判据 | 最好的衰减配置 vs off | 是否 ≥5% |
|---|---|---|
| S1 ÷ 诚实 | on720 +0.07%（方向变差） | 否 |
| S2 越线 | 0% | 否 |
| S3 潜伏者 | on24 −3.54% | 否 |
| S3 渗透 | on24 −6.08% | 是（但 CI 跨 0） |
| S3 背书 | on24 −10.39% | 是（CI 不含 0） |
| S4 | 0% | 否 |
| S5 单来源上限 | on24 **+239.7%（恶化）** | 反向 |
| 攻击残余（非 S 判据） | on24 −104%、on72 −74.7% | 远超 5% |

**判断：**
1. **严格按 S1~S6**：前提基本成立（8 条里只有 S3 的两条达到 5%：渗透 −6.08% 但 CI 跨 0、
   背书 −10.39% 且 CI 不含 0；其余 ≤4% 或为 0；S5 反向恶化），
   所以「建议删除」**在 S1~S6 口径下是成立的**。
2. **但删除必须写明代价**：攻击残余会从 72h 的 0.250 回到关闭时的 0.990（+296%），
   也就是一次已经结束的攻击，600h 后仍保留 99% 的伤害。
3. **我的建议：不直接删，改为「留但降级」**——把衰减从「反女巫机制」重新定义为「伤害时效机制」：
   - 存在理由：唯一能压攻击残余的机制（−74.7% @72h，−104% @24h）；
   - 代价：S5 单来源上限被放大 1.6~3.4 倍；
   - S1~S6 上它没有可测的正面贡献（≤4%，CI 全跨 0，S5 反向）。
4. **如果作者只认 S1~S6、不认「攻击残余」**：那就删。删掉后 S1/S2/S4/S6 一位不动，
   S3 变差 0.1~10%，S5 恢复 1.0×，攻击残余回到 99%。这不是数据能替作者做的决定。

## 6. 两套仿真器：每条结论到底出自哪里

### 6.1 溯源表

| 结论 | 数字 | 出自哪个 bin | 引擎还是 run_case | 可信度 |
|---|---|---|---|---|
| S1 女巫传播后 0.000 | 0.000 | L3（Engine）；本报告 2.9 在 Engine 上复现 | Engine | **高**（80/80 次运行精确 0） |
| S2 16632 注入 5 个越线 | 0.03% | **L3**（3 seed × 44 潜伏者 × Σ(1+5+20+100)=126 → 16632） | Engine | **高**（本报告 4800+2400 次注入零越线，同向） |
| S3 渗透 2.29 / 背书 1.97 | 2.29 / 1.97 | 交接文档标「真多 runtime」，未指名 bin（D1/D2/L4 系列） | Engine | 中高（场景参数不同，本报告 6.3 无法精确复现这两个数） |

| sybilcap 的「有效女巫」表 | 单 seed、最多 50 注入 | sybilcap | **run_case** | 仅方向性 |
| factorial 的 2×2 女巫比值 | 单 seed | factorial | **run_case** | 仅方向性 |
| e2e / dist / splitnorm | — | 三者 | **run_case** | 仅方向性 |

**更正一条误传**：S2 的「16632 注入 5 个越线」**不是** sybilcap 的数字。sybilcap 是 59 行的单 seed 探针
（n_sybil ∈ {1,5,20,50} × 2 种归一化），注入总数最多 50×2；16632 = 3×44×126 正好等于 L3 的 60 格网格，
而 L3 用的是 tm_engine。所以这条结论本身站在真 runtime 上。

### 6.2 d2_response / l4_olduser / l5_health 实际调用的是哪一套？

逐行确认：三个 bin 里的 run_case 都是**自己定义的同名函数**：

- d2_response.rs:419  fn run_case(m: Mode, seed, n_sleep, dorm, variant) -> RunOut  —— 函数体里建 tm_engine::Engine、调 tick / on_view；
- l4_olduser.rs:302   fn run_case(p_target, d, seed, dormancy, attack) -> RunOut     —— 同上；
- l5_health.rs:235    fn run_case(seed, s, p_target, dormancy, sleep) -> Run           —— 同上。

三者**都没有** use tm_exp::...，也没有 run_case_full。grep 命中的 run_case 是局部函数名，
不是副仿真器。**结论：D2 / L4 / L5 全部由真 runtime 驱动。**

### 6.3 run_case_full 与 Engine 的逐条口径差（位置 / 两边公式 / 实测偏差）

同输入世界：n=400、steps=120、Infiltrator 8%、follow 30~45、seed=11；注入 50 个女巫 + 48 个空账户。

| # | 位置 | run_case_full | Engine | 实测偏差（表 RC） |
|---|---|---|---|---|
| 1 | 个人项 | 原始评分 s；声望 = β·s + (1−β)·g | 份额 s/Σs；声望 = β·(s/Σs) + (1−β)·g | 诚实均值 0.1308 vs 0.00225（**58×**）；S3 比值 1.91 vs 2.16 |
| 2 | 时间 | 无衰减 | 0.5^(Δt/H)（基准 last_check） | 残余 0.99（无）vs 0.25（72h）；S3 只差 2%（120h 窗口短） |
| 3 | 噪声底 | 硬编码 1e-6 | 观点自估噪声中位数（本实验里中位数常为 0） | 空账户在两边都是 0（表 RC 的 empty_ratio 列） |
| 4 | 接收方归一化 | 默认关（view_mass=1）；开时除以 Σv | 无条件除以 total_mass | 女巫比值 0.0248 → 0.0177（关闭 vs 打开，**1.4×**）；收益方 1.91 → 2.14 |
| 5 | 抽样 | 每轮固定 k 独立随机（可跨轮重复） | 轮次位图一轮不放回 + 连败退避 | 未单独量化；影响来源新鲜度分布 |
| 6 | 初始观点 | 每人用自己的评分表当初始观点 | 初始空视图，首轮才拉到 | 前几轮尺度不同 |
| 7 | 发布集合 | 所有账户每轮都发布（rep 行） | 只有在线且被抽到的才发布 | 离线节点在副仿真器里不会「失声」 |
| 8 | 量的定义 | rep 是 0~1 的个人评分，**不满足总和=1** | trust_distribution **总和恒为 1** | 两边的「均值」不是同一量纲，只有比值可比 |

**结论**：副仿真器可以回答「机制方向对不对」的定性问题，但**不能**用来支撑 S2/S3 的数值结论，
更不能回答任何与时间/衰减有关的问题。历史 S2 数字出自 L3（Engine），不受影响；
sybilcap / factorial 的数字只能当方向性参考。

## 7. 建议（删 / 改 / 留）

### 删（候选）

1. **crates/exp 的 5 个副仿真器 bin**：e2e、dist、factorial、splitnorm、sybilcap。
   理由：与 Engine 的口径差 1.4~58×，无法支撑任何 S 判据；sybilcap / factorial 的「有效女巫」表
   在 Engine 上无法复现（表 RC）。删掉后 tm_exp::run_case_full 也没有调用者了，可一并删。
2. **S2 的「越线数」判据**：在 60%/90% 离线、4800/2400 次注入下恒为 0，没有判别力。
   建议改为报告 **S1 比值**（连续量，本报告 0.0274~0.0284）。

### 改

1. **把衰减的存在理由从「反女巫」改成「伤害时效」**：S1~S6 上它贡献 ≤4% 且 S5 反向；
   唯一一阶效应是攻击残余（72h −74.7%、24h −104%）。规格里要写清这一点。
2. **把 S5 的新失效面写进威胁模型**：衰减让「保持新鲜的单来源」突破等新鲜度上限 1.60~3.40 倍；
   如果反女巫是主目标，这个套利必须被承认（或给衰减加一个「来源新鲜度上限」）。
3. **D1/D2 的 landed 前提硬化**：exp_n=0 的格子必须报错而不是照常输出 p_ratio（A4-07）。
4. **S4 的判别力**：300 人规模下空账户精确为 0，等于没测。要做 A1/A2（噪声底随规模）才能说 S4 真的成立。

### 留

**衰减（decay_enabled / half_life / decay / decay_factor）建议留，但按上面第 1 条重新定位。**
数字依据：
- 对 S1/S2/S4/S6 的贡献 ≤4%（CI 全部跨 0），对 S5 是 −60%~−240%（恶化）→ 按 S1~S6 它「可以删」；
- 但它把攻击残余从 0.990 压到 0.250（72h）/ −0.043（24h），这是任何其他机制都做不到的；
- 删除的代价明确：S3 变差 0.1~10%，攻击残余回到 99%，D2/D4 的结论全部作废。

**如果作者只认 S1~S6、不认「攻击残余」这一维度**：那就删，删掉后 S1/S2/S4/S6 一位不动。
这个决定需要作者拍板，数据本身不能替他做。
