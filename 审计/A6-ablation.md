# A6 —— 逐机制消融：删了反女巫也不变差的清单

> 目标：把已实现的机制**逐个关掉**，看 6 条反女巫判据（S1~S6）变化多少。关掉后不变的，就是可以删的。
>
> **全部 S1~S6 数字都跑在真实 runtime 上**：每账户一个 tm_engine::Engine，走 rate / tick / on_view /
> query / trust_distribution。**没有**使用集中式近似 tm_exp::run_case_full（它是副仿真器，口径差异见第 10 节）。
> 唯一例外是 M4（换精确稀疏表）：引擎的 on_view 只收 CompressedView，换存储必须在 bin 里重写传播链；
> 那条链的 Sketch 臂与真引擎**逐值相同**（第 6 节给出对照），只有「观点的存储表示」这一项被替换。

---

## 0. 一句话结论

1. **S1 和 S2 的"预算封顶"与这 8 个机制几乎无关**：16 个变体 × 8 seed，女巫在诚实观察者眼里恒为
   0.000，注入女巫越线率恒为 0/61,960。**删掉任何一个机制都不会破坏 S1/S2。**
2. **只有 S3 有区分度**：收益方倍数 1.695±0.415（渗透）/ 4.105±0.696（背书）。
   等权是最有效的轻量改动（−0.542 / −2.152）；**cap = 2×均值完全无效（−0.004 / −0.025）**，
   因为单个满分来源的份额（1.88×均值）刚好在 cap 之下。
3. **S4 从未测过，一测就失败**：空账户平均拿到诚实账户 **0.78%** 的声望，2.5% 的空账户非零，
   **单个最高 31.3%**。根因是 Count Sketch 碰撞；换成精确稀疏表 S4 直接归零，而 S1/S2/S3 只动 <0.2%。
4. **S5 失败**：单个来源伪造「我给我自己 1.0」，自身声望 ×1.826；最小复现 ×15。total_mass 防线
   只在「接收方认识观点里那些密钥」时有效。
5. **S6 全绿**：15 个变体 × 94,464 个数值，两次运行最大差 0。
6. **M7 噪声底、M8 MAX_SCORE 是死代码**：关掉后 8 个 seed 的每一个判据配对差都是 0.0000±0.0000；
   噪声底中位数实测恒为 0（p95 也是 0），过滤分支永不触发。
7. **β 是唯一"动一个旋钮就能让 S3 通过"的参数**：β 从 0.3 抬到 0.9，收益方倍数
   渗透 1.695 → 0.355、背书 4.105 → 0.728，**双双跌破 1**；同时 S2/S4/S5 也单调变好。
   这与交接文档「提高 β 无效（0.3→0.9 比值纹丝不动）」**直接矛盾**——那条出自副仿真器（见第 5.1 节）。
8. **M9（群体项分母算全部来源）在本实验里没有收益**：M/N ≈ 1，所以它与基线几乎同值
   （S3 收益方 1.707 vs 1.695），而 S2 反而变差 54%。它的作用只在 M≪N 时出现：
   M=1/N=100 的极端把 236.67× 压到 3.33×（第 5.5 节，精确复现 A1 的 236.67）。

## 1. 方法

### 1.1 拓扑与时间轴

| 项 | 取值 |
|---|---|
| 人口 | n_initial = 200，跑 100 步（=100 小时），join_rate 0.15、leave_rate 0.00012（默认） |
| 关注 | follow_min=20 / follow_max=30 / max_follows=40（与 multinode 一致） |
| 传播 | 世界结束后再交换 **4 轮**，每轮 **24 小时**，最终统计时刻 now = 100 + 3×24 = **172** |
| 抽样 | 每轮每引擎 tick(now, 12)；M5 变体改用 probe(now)（= draw_all） |
| 视图 | 2048 桶 × 5 行，seed = 99 |
| 攻击 | attack_ratio = 0.08（渗透 16 人 / 背书 40 人 / 女巫 16 人、3 集群）+ 1 个 Promoted 收益方 |
| seed | **11, 12, ..., 18 共 8 个** |

**为什么每轮 24 小时**：multinode 里 now = 轮次序号，所有观点年龄恒为 0，衰减是空转。
本实验把 4 轮铺开成 96 小时，观点年龄覆盖 0/24/48/72 小时，正好一个半衰期——只有这样 M3 才有东西可测。

### 1.2 判据定义（全部固定，先定后测）

观察者 = **活着的诚实账户**；分布 = trust_distribution(now)（总和恒为 1）；
hm = 该观察者眼中所有诚实账户的均值；所有比值 = 该账户在分布里的值 ÷ hm。

| 判据 | 定义 | 取自哪个场景 |
|---|---|---|
| S1 | 女巫集群成员的均值 / hm；并报"出现率"（分布里非零的比例） | sybil |
| S2 | 注入女巫均值 / hm；**越线率** = 超过 hm 的（观察者,女巫）对 ÷ 全部对 | infiltrator |
| S3 | 收益方（Promoted）的 dist 值 / hm；另报攻击者自己 / hm | infiltrator + endorser |
| S4 | 40 个「已 intern 但没人评分」的新密钥：均值 / hm、单点最高 / hm、出现率 | infiltrator |
| S5 | 把一个**已被诚实观察者评分**的来源的观点换成伪造视图后，它自己的声望 ÷ 伪造前 | infiltrator |
| S6 | 同输入重跑，全部（观察者 × 账户）声望矩阵的最大绝对差 | 全部 |

**S2 的注入方式**：世界结束后，选出度最大的攻击者，给它注入 40 个新账户各 1.0 分，然后照常传播。
注入女巫作为额外账户被每个引擎 intern（模拟"它们主动接触过一次"）。观察者 × 女巫对 = 1549 × 40 = **61,960**。

**S5 的测法**：先用伪造者自己的真实视图给所有诚实观察者 on_view 一次（把年龄固定为 0，排除衰减混淆），
得到 R0；再换成伪造视图得到 R1。R1/R0 就是"自吹的收益"。
"自吹" = 视图里只写一条（自己，1.0）；"塞壳" = 再塞 200 个观察者已认识的空壳账户各 1.0（试图把 total_mass 撑大）。

### 1.3 与 multinode 的差别

| 项 | multinode | 本实验 |
|---|---|---|
| 时间轴 | now = 轮次（年龄恒 0，衰减空转） | 每轮 24h（年龄 0~72h，衰减生效） |
| 判据 | 只报攻击者/诚实比 | 6 条判据 + 空账户 + 伪造 |
| 规模 | 200 账户 × 100 步 × 4 轮 × k=12 | 同（额外 280 个账户用于 S2/S4/S5） |

把 multinode 的口径复现出来校准：渗透 2.290、背书 1.966、女巫 0.000、垃圾 0.031 —— **与交接文档的
2.29 / 1.97 完全一致**。所以本实验的基线可以与该文档横向比较（差别只在时间轴）。

## 4. M1 重点：等权 / 份额上限能不能把 S3 压下来

**结论：cap = 2×均值 完全无效；要有效必须 cap ≤ 1.5×；等权（= cap 1.0×）也只是把 1.695 压到 1.153，压不到 1。**

| 方案 | S3 收益方(渗) | S3 收益方(背) | S3 攻击者(渗) | S2 注入均值 | S4 | S5 |
|---|---:|---:|---:|---:|---:|---:|
| 基线（份额 = 评分/Σ评分） | 1.695±0.415 | 4.105±0.696 | 2.127±0.200 | 0.0301 | 0.0078 | 1.826 |
| cap = 2.0×均值 | 1.691（−0.004±0.005） | 4.080（−0.025±0.013） | 2.126 | 0.0301 | 0.0078 | 1.825 |
| cap = 1.5×均值 | 1.435（−0.260±0.065） | 3.389（−0.716±0.115） | 2.057 | 0.0294 | 0.0079 | 1.826 |
| cap = 1.2×均值 | 1.181（−0.514±0.132） | 2.721（−1.384±0.231） | 1.933 | 0.0278 | 0.0082 | 1.826 |
| 等权（cap = 1.0×） | **1.153（−0.542±0.246）** | **1.953（−2.152±0.472）** | 1.571 | 0.0187 | 0.0096 | 1.826 |

**为什么 cap=2× 一点用都没有**：一个观察者平均给 18.7 人评分，均分份额 = 1/18.7 = 0.0535；
一个满分来源的份额 = 1.0/9.93 = 0.1007，只有均值的 **1.88 倍** —— 刚好在 2.0 的 cap 之下，**一次都没被削到**。
这正好印证了"污染比 ≈ 2 是结构性常数"的诊断：它不是某个离群点，而是"一个 1.0 对上一群 0.5"的平均效应，
削单个离群点的 cap 打不到它。

**对 S2 的副作用**：没有。所有 cap 与等权的越线率都是 0/61,960，注入均值反而下降（0.0301 → 0.0187，−38%）。
**对 S4 的副作用**：略差（0.0078 → 0.0096，+22%），因为诚实账户的份额被拉平后，空账户的相对基数变高。

**代价**：等权丢掉了"评分强度"这个语义（0.1 分和 1.0 分一样重）。如果作者要保留强度，
cap 1.2× 能拿到等权 95% 的收益（渗透 1.181 vs 1.153），但背书差 39%（2.721 vs 1.953）——
因为背书是**40 个来源同时**抬，1.2× 的 cap 挡不住"人多"。

## 5. 逐机制解读

### M2 β 混合（β = 0 / 0.3 / 1）

- **β = 0 直接把系统打死**：第 0 轮还没有任何观点，群体项为 None、个人项又被乘 0 ⇒ 所有账户声望 = 0 ⇒
  导出的观点是空视图 ⇒ 之后永远全零。8 个 seed 无一例外（全部判据 NA）。
  **个人项是传播的种子，β 不能为 0。**
- **β = 1**：声望退化为"我自己的份额"，S2/S3/S4/S5 全部归零——但代价是群体项完全不存在，
  也就是说这套系统不再是"听别人怎么说"的网络，退化成每个人自己的评分表。这不是防住，是取消了功能。
- β = 0.3 的基线：S3 收益方 1.695（渗透）/ 4.105（背书）。

1. **收益方倍数随 β 单调下降**：渗透 −84%（2.262→0.355）、背书 −87%（5.473→0.728）。
   β ≥ 0.9 时两条都跌破 1 ⇒ **S3 通过**。这与交接文档 5.3「提高 β 无效（0.3→0.9 比值纹丝不动）」
   直接矛盾；后者出自 crates/exp 的集中式框架（个人项用原始评分，见第 10 节差异 #1）。
2. **攻击者自己的比值几乎不动**（2.127→2.232 / 1.867→2.089）：β 动的是"收益方能不能被抬起来"，
   不是"攻击者自己有多少声望"。这也解释了为什么当年用"攻击者比值"扫描 β 会得出"无效"。
3. **S2/S4/S5 一起变好**（注入均值 −91%、S4 −99%、S5 −47%）。β 是唯一一个"只调参数、不改结构"
   就能同时改善 4 条判据的旋钮；代价是群体项的话语权从 70% 降到 10%。
   与 A1 的解析式 D[T] = β/N + (1−β)/M 对照：A1 的 3.33×（β=0.3、M=N、观察者给收益方打过分的口径）
   对应本表里"最高的那部分观察者"，而本表是**全部**诚实观察者的平均（含从没给收益方打过分的），
   所以绝对值更低但趋势一致。

### M3 来源级衰减（decay_enabled = false）

关掉后：ΔS3(渗) = −0.0017±0.0054、ΔS3a = −0.0003±0.0010、ΔS2 = +0.0004、ΔS4 = −0.0006、ΔS5 = **−0.101±0.011**。
**方向不一致、量级 ≤ 8%，而且 S4/S5 还略微变好。**
→ 从反女巫角度，衰减的贡献是 0。它是否保留应该由"遗忘/抗离线"的需求决定（交接文档 5.4 已证伪它原本的目的），
**不能用反女巫当理由**。

### M5 退避抽样（draw_backoff → draw_all）

ΔS3(渗) = −0.0003±0.0257（在噪声内）、ΔS3a = +0.0014±0.0111、ΔS2 = −0.0016、ΔS5 = −0.099。
唯一显著的是 **ΔS4 = +0.0057±0.0029（+72%）**：恒抽全量让每个引擎缓存更多来源的观点，
噪声碰撞的机会变多，空账户漏到的声望更多。
→ 退避对反女巫没有可测贡献；它省的是带宽。S4 变差是压缩的锅，不是抽样的锅。

### M6 聚合口径（Mean / Median / WMedian / Trimmed(0.1)）

- **Median / WMedian 是伪防御**：19 个来源里对某个目标"没表态"的占多数，中位数落在 0，
  群体项对几乎所有账户恒为 0。于是 S2/S4 看起来变成 0、S5 变成 1.0——
  这不是"更抗女巫"，而是"没有群体意见了"（等价于把 β 抬到 1 的退化）。
- **Trimmed(0.1) 反而更差**：S3 收益方 +0.374±0.447、攻击者 +0.446±0.168。
  两端各裁 10% 权重，裁掉的低分来源正好是"稀释抬举"的那部分，剩下的人均更高。

### M7 噪声底（两种用法分开评估）

**用法①：当中位数门限（引擎现在的用法）。**
关掉 noise_multiplier（1 → 0）后：8 个 seed × 5 个判据的配对差**全是 0.0000±0.0000**（逐位相同）。
原因：噪声底取的是 1000 个随机 key 的**中位数**，实测在 50/200/1000/4000 条写入下 median **恒为 0**
（噪声分布极度右偏，中位数把尾部整个丢掉）。所以门限恒为 0、过滤分支永不触发 ——
**它不是"有点弱"，是从来没执行过。**
A3 独立测到同一结论（清单 ≤1000 时 FPR=100%，一个空账户都挡不住；≥10000 时开始误杀 51% 真实条目）。
本报告补的曲线（第 6 节表）：m=4000 时中位数仍为 0，但真实条目已有 2.0% 被它误杀 ——
**门限这一用法在两端的表现都不可接受**。

**用法②：当"这份观点整体是否可用"的判据（尚未实现）。**
这条本报告没有测（引擎里没有这个分支），但数据支持它有信息量：p95 随 m 变化（m=1000 时 0.001、
m=4000 时 0.00025），而 max 恒为 0.005 —— 也就是说"整份观点的噪声幅度"是可观测的，
可以拿来做"这份视图该不该被信"的门槛，而不是拿它去筛单个读数。
**建议：删除用法①（43 行 + 每次 on_view 的 1000 次查询），把用法②留作待验证项。**

### M9 群体项分母（只算已缓存来源 vs 算全部已评分来源）

现状：群体项的分母 Σw 只含"有缓存观点"的来源；反事实：Σw 计入全部已评分来源，没观点按 0 算。

**数学上它就是 s = coverage**：Σ_live w·v ÷ Σ_all w = (M/N) × (Σ_live w·v ÷ Σ_live w)。
所以它能用**现有配置精确实现**（unreachable_after 取极大 + remove_when_coverage > 1 + coverage_exponent = 1
+ group_half_life = 0 ⇒ s = M/N），不需要改库。

| 情形 | 现状 | 反事实 M9 | 差 |
|---|---:|---:|---|
| 本实验（M≈19、N≈18.7，M/N ≈ 1.0）S3 收益方(渗) | 1.695±0.415 | 1.707±0.418 | +0.7% |
| 本实验 S3 收益方(背) | 4.105±0.696 | 4.092±0.685 | −0.3% |
| 本实验 S2 注入均值 | 0.0301 | **0.0463** | **+54%（变差）** |
| 本实验 S4 空账户 | 0.0078 | 0.0074 | −5% |
| **M=1 / N=100 极端**（单测） | **236.67×** | **3.33×** | −98.6% |

**结论**：M9 的效应严格等于乘 M/N。
- 网络健康（每个引擎缓存的观点数 ≈ 正分清单长度）时，M/N ≈ 1，**它什么也不做**，还让 S2 变差
  （因为个人项不随 s 缩放，缩放只打群体项，空账户/注入女巫的相对比值反而上升）。
- 只有在"能看到的来源远少于认识的来源"（回归者、大规模离线、只连得上攻击者）时它才救命：
  M=1/N=100 时把 236.67× 压到 3.33×——**精确复现 A1 的 236.67×**（A1 的反事实报 21.79×，
  差异在 coverage 的分母口径：本测试取 N=100；若分母更小，压缩倍数更小，建议与 A1 对齐口径）。
- 它已经藏在现有配置里（s = coverage），所以**不需要新机制**；要不要打开取决于"是否愿意在覆盖率低时
  放弃群体意见"。

### M8 MAX_SCORE（1e9 上限 vs 1.0 归一化输入）

- **输入 ×10000（模拟应用层传原始计数）**：结果与基线**逐位相同**（Δ 全 0）——份额是比例，尺度不变，
  1e9 的上限根本没碰到。
- **把输入夹到 1.0**（模拟 MAX_SCORE = 1.0）：结果与 **m1_equal 逐位相同**
  （hm 0.00469170、S3 收益方 1.15263850、S3 攻击者 1.57099475、S4 0.00955261 —— 与 m1_equal 的 8 位数完全一致）。
  因为原始计数都 > 1，夹到 1.0 就等于"所有人一样重"。
- 结论：**MAX_SCORE = 1e9 是死代码**；改成 1.0 不改变反女巫，只会改变应用层语义（原始计数被压平）。

## 6. M4：Count Sketch 压缩值不值

引擎的 on_view 只接受 CompressedView，所以换精确稀疏表必须在 bin 里重写传播链。
为了证明"只有表示不同"，那条链做了两件事：
1. 抽样用同一套 tm_store::RoundSampler + Rng（连败全 0 时 draw_backoff 与 draw 逐位相同）；
2. Sketch 臂与原引擎跑同一组 seed，**逐值对照**。

对照结果（infiltrator，8 seed）：Sketch 臂与真引擎的 6 个指标在 8 位小数上完全相同
（hm 0.00448932、S2 0.03008634、S3 收益方 1.69495723、S3 攻击者 2.12694265、S4 0.00782821、S4 最高 0.31312822）。

| 判据 | 2048×5 Count Sketch | 精确稀疏表 | 差 |
|---|---:|---:|---:|
| S1 女巫 | 0.000 | 0.000 | 0 |
| S2 越线率 | 0/61,960 | 0/61,960 | 0 |
| S2 注入均值 | 0.03009 | 0.03013 | +0.13% |
| S3 收益方(渗) | 1.6950 | 1.6976 | +0.15% |
| S3 攻击者(渗) | 2.1269 | 2.1287 | +0.08% |
| S3 收益方(背) | 4.1050 | 4.1126 | +0.19% |
| S3 攻击者(背) | 1.8668 | 1.8681 | +0.07% |
| **S4 空账户均值** | **0.00783** | **0.00000** | **−100%** |
| **S4 单点最高** | **0.3131** | **0.00000** | **−100%** |

**压缩在 S1/S2/S3 上是免费的（差 <0.2%），唯一的代价是 S4。** 而 S4 正是从未测过的那一条——
一测就是失败项。

**按 A3 的口径重述这笔交易**（"同一 S4 水平下谁更小"，而不是"同一体积下谁更准"）：
精确表要 4 字节/条 ⇒ m 条只要 4m 字节（m=1000 → 4KB，A3 实测 18–36KB 是因为带了额外结构）；
而 2048×5 的 sketch 是固定 40KB。本报告在草图层面量了泄漏随写入量 m 的变化（2048×5）：

| m（视图条目数） | 噪声底中位数 | 空密钥「读数非零」比例 | 真实条目被中位数门限误杀 |
|---:|---:|---:|---:|
| 50 | 0 | 0/500 | 0/50 |
| 200 | 0 | 0/500 | 0/200 |
| 1000 | 0 | 38/500（7.6%） | 0/1000 |
| 4000 | 0 | 215/500（43%） | 82/4000（2.0%） |

即：**m ≥ 1000 之后 sketch 的空账户泄漏随 m 快速上升（7.6% → 43%），而中位数门限仍是 0。**
A3 在引擎层面量到 m=1000 时 30.4% 的空账户出现率，与本表的趋势一致（口径不同：本表是草图单点非零，
A3 是引擎分布里出现）。所以"用 40KB 换定长"的代价不是"精度差一点"，而是**在 m≥1000 时 S4 系统性失守**；
若要靠加大桶数解决，桶数需要随 m² 增长，40KB 的定长优势会先消失。
**结论：在 S4 这一条上，精确表在 m ≤ 几千的规模里既更小也更安全；sketch 的价值只剩"体积与账户数无关"，
而账户数在 m 上的表现恰恰是它的软肋。**

| 「提高 β 无效，0.3→0.9 比值纹丝不动」 | — | 出处未注明（crates/exp 框架） | **近似** | ❌ 被真引擎证伪 | β 0.3→0.9：收益方 1.695→0.355（渗）/ 4.105→0.728（背）——**有效** |
| factorial：30 抬 1 = 3.13× / 分散 0.099× | 3.13 / 0.099 | factorial | **近似（run_case_full）** | ❌ 不可作依据 | 未重跑（超出 A6 范围） |
| D1~D4 / L1~L5 / multinode / latent / grid | — | d*/l*/multinode/latent/grid | 引擎 | ✅ | 佐证：multinode 2.290/1.966 复现 |

**逐行确认 d2_response / l4_olduser / l5_health 用的是哪一个**：这三个文件里都有名为 run_case 的函数，
但都是**本地定义、引擎驱动**的：
- d2_response.rs:419 fn run_case(m: Mode, seed, n_sleep, dorm, variant) -> RunOut（内部 Engine::with_seed + tick + on_view）
- l4_olduser.rs:302 fn run_case(p_target, d, seed, dormancy, attack) -> RunOut（同上）
- l5_health.rs:235 fn run_case(seed, s, p_target, dormancy, sleep) -> Run（同上）

全文检索：use tm_exp 只出现在 e2e.rs / factorial.rs / splitnorm.rs / sybilcap.rs / dist.rs；
run_case_full 只出现在 factorial.rs 与 splitnorm.rs。**所以 D1~D4、L1~L5 的头部结论出自引擎，可信。**

## 10. 副仿真器（run_case_full）与引擎的逐条口径差异

同一份世界、同一组 seed、同一套判据定义，两边各跑一遍：

| 判据 | run_case_full | 引擎 | 偏差 |
|---|---:|---:|---|
| S1 女巫 | 0.000 | 0.000 | 0 |
| S2 越线率 | 0/63,240 | 0/61,960 | 0 |
| S2 注入女巫均值 | 0.0123 | 0.0301 | **−59%** |
| S3 收益方（渗透） | 0.560 | 1.695 | **−67%** |
| S3 攻击者（渗透） | 2.220 | 2.127 | +4% |
| S3 收益方（背书） | 1.216 | 4.105 | **−70%** |
| S3 攻击者（背书） | 2.022 | 1.867 | +8% |
| S4 空账户 | 0.0000 | 0.0078 | 量不到 |

**读法：副仿真器把"攻击者自己"的倍数算得很准（差 4~8%），却把"收益方被抬到几倍"系统性低估 67~70%。**
所以 e2e 的"渗透 1.886 / 背书 1.814 反向放大"定性结论成立（方向对），但**倍数量级不可用**；
S2 的"越线率"方向也对，但注入均值同样被低估。

### 逐条差异

| # | 位置 | run_case_full | 引擎 | 造成的偏差（实测/推导） |
|---|---|---|---|---|
| 1 | exp/lib.rs:189 | personal = 观察者给目标的**原始评分** | personal = 评分 ÷ Σ评分（份额） | 个人项被放大 Σ评分 倍：实测平均给 18.7 人评分、Σ=9.93 ⇒ 个人项 0.054 → 0.53（**9.9×**）；β=0.3 时这一项从 0.016 抬到 0.16 |
| 2 | exp/lib.rs 全文 | **无时间衰减** | 0.5^(Δt/72) 逐来源 | 由 M3 变体实测：关掉衰减后 S1~S5 变化 ≤8%（S3 −0.002、S2 +0.0004）⇒ 这一条对判据影响很小，但它决定"老观点"的相对权重 |
| 3 | exp/lib.rs:193 | v < 1e-6 就置零 | v < noise.median × mult | 引擎实测 noise.median 恒为 0 ⇒ 两边都等于不筛，**偏差 0** |
| 4 | exp/lib.rs:195 | 只有 receiver_normalizes=true 才除估计质量 | **无条件**除以 total_mass | 副仿真器默认关（e2e 里显式打开），关了来源可以整体放大自己的读数；引擎侧这条防线本身也能被绕过（D2/D4） |
| 5 | exp/lib.rs:181-185 | 每轮独立 Fisher-Yates，可重复抽同一来源 | 轮次位图 + 退避，一轮内不重复 | 4 轮 × k=16、清单 18.7 项：引擎两轮覆盖全部，副仿真器期望覆盖 1−(1−1/18.7)^64 ≈ 97% ⇒ 抽样差异 <5% |
| 6 | exp/lib.rs:143-152 | 第 0 轮发**原始评分** | 每轮发 query() 归一化声望 | 第 0 轮量级差 Σ 倍；M2 β=0 证明"第 0 轮必须由个人项播种"，否则全网恒 0 |
| 7 | exp/lib.rs:194 | exclude_zero=true：没表态的来源不进分母 | 0 值照样进分母 | 实测 ez=1 vs ez=0：S3 收益方 0.560→0.567（+1.2%）、S2 0.0123→0.0093（−24%）⇒ 影响 <25%，不是主因 |
| 8 | exp/lib.rs:137 | others = 攻击者 + 收益方（混合） | 分开统计 | 若按 others 算 S3，会被收益方稀释；这是"2.29 被当成收益方"的第二个来源 |
| 9 | exp/lib.rs:118 | n = max(o,t)+1 + extras | 观察者 intern 全部已知账户 | 归一化分母不同 ⇒ hm 差 3.5×（0.0155 vs 0.00449）；比值本身免疫，但绝对量级不可比 |

**副仿真器还能不能用**：能用来判断"方向"（女巫不可达、渗透/背书防不住、越线率极低），
**不能用来给出倍数与量级**。S2 的"16632 里 5 个越线"这类数字必须用引擎重跑（本报告已重跑：0/61,960）。

## 12. 局限（没做的事）

1. **规模只到 ~210 个存活账户**。S4 的碰撞率与视图条目数强相关（本实验里传播 4 轮后视图变得很稠密），
   没有验证 1000+ 账户时 S4 会变好还是变坏。
2. **M2 β=0 的 S1~S5 无法定义**（全网归零），表中记为"全网归零"而不是 0。
3. **M4 只换了存储表示**，没有测带宽/体积；也没有测"加大桶数"这条中间路线（2048 → 8192）。
4. **S2 只测了"越线率"与"注入均值"**，没有重跑交接文档里"预算按 1/(S0+N) 稀释 / 拉一个有效女巫需要份额 0.36~2.05"这条单点结论。
5. **S5 只测了"自吹"与"自吹+已认识壳"两种伪造**，没有测"伪造大量陌生 key 把 total_mass 抬高再夹带自己"的组合。
6. **背书场景只跑了 base / m1_equal / cap / beta 变体**（其余机制对背书场景未测）。
7. 每轮 24h 的设定是我选的（为了让衰减有东西可测）；它会影响 S3 的绝对值，与 multinode 的"年龄恒 0"口径不可直接相减。
8. **M9 的反事实只测了一个极端（M=1/N=100）与一个健康态（M/N≈1）**，中间地带（M/N = 0.1~0.5，例如大规模离线）
   没有扫描；A1 报的 21.79× 与本测试的 3.33× 差异来自 coverage 分母口径，尚未对齐。
9. **β 扫描只跑了渗透与背书两个场景**，女巫场景没有扫（S1 在 β=0.3 时已恒为 0，预期不受影响但未测）。
10. 新增的 M9/β 变体只在 infiltrator / endorser 上跑；m9_coverage 的 S1/S6 记为"未测"（它在结构上不改变
    "女巫不在任何诚实清单里"这条，但按纪律不臆测）。
