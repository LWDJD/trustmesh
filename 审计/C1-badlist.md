## 0. 一页结论

**建议保留变体 U（统一折扣），默认关闭，只在应用层有高置信度「正在攻击我」的账户时启用。不建议启用变体 P。**

| 问题 | 答案 |
|---|---|
| S3 收益方降了多少？ | 从 4.288 降到 3.524（相对 **17.8%**），没有回到 1 |
| S3 攻击者（购买者本人）降了多少？ | 基本没变（2.080 → 2.069）：badlist 削的是**话语权**，不是他们收到的评分 |
| ρ 排序质量掉多少？ | -0.0003，可视为不变 |
| 被罚来源平均折扣 | 0.720（攻击者来源平均 0.736） |
| 误伤：诚实来源被罚 <0.9 的比例 | **11.1%** |
| 错罚全部购买者会怎样？ | 误伤 **90.9%**，S3 只降 5.1% —— 不能乱罚 |
| 全圈对 A 态度一致时会怎样？ | S+ 为空，f = 1，折扣全 1.0（精确退出） |

一句话：**它能削掉攻击放大的约五分之一到四分之一，代价是约一成诚实来源被误伤；它抓不到「整个圈子一致包庇 A」，也不改变购买者本人的声望。**

## 1. 动机与定位

攻击者 A 通过「我信任的某些来源」把同伙传导进我的视野。整套设计里其它机制都只看
「你评了谁」，只有 badlist 看「你**护**了谁」：

- 应用层负责判断「我正在被谁攻击」，把账户号交给引擎；
- 引擎看**我信任的来源**里，谁对 A 的评价明显高于平均；
- 把这些人对 A 的「额外热情」折算成对**来源话语权**的折扣。

名字是 **badlist**（不是 banlist）。它不删除任何评分、不阻断任何账户、不做 I/O。

---

## 2. 接口

```rust
impl Engine {
    pub fn set_badlist(&mut self, ids: &[AccountIdx]);   // 覆盖，自动排序去重
    pub fn add_badlist(&mut self, id: AccountIdx);       // 追加，已存在则无操作
    pub fn clear_badlist(&mut self);                     // 清空
    pub fn badlist(&self) -> &[AccountIdx];              // 升序去重后的清单
    pub fn badlist_discount(&self, idx: AccountIdx) -> Score; // [0,1]，1 = 未罚
    pub fn recompute_badlist(&mut self);                 // 立即重算（tick 也会自动调）
}
```

语义细节：

- `set/add` 只改清单；折扣在下一次 `recompute_badlist()` 或 `tick()` 时更新；
- `clear_badlist()` 在 α = 1（默认）时**立刻**丢弃折扣表；α < 1 时保留旧值，
  由后续重算逐轮恢复；
- `recompute_badlist()` 没有 `now` 参数：时间基准是引擎最近一次带时间参数的调用
  （`tick` / `rate` / `on_view` / `probe` / `prune_stale`），一次都没调过时为 0；
- `tick(now, k)` **开头**自动重算，然后才抽样；
- badlist 只影响群体项权重，不影响抽样、覆盖率、live 判定、个人评分。

## 3. 算法

### 3.1 读数与权重

对每个来源 v（我给它正分、有观点缓存、权重大于 0）：

```text
a_v = 观点[v] 对攻击者 A 的读数     // 除以 total_mass，夹到 [0,1]，低于噪声底视为 0
w_v = 份额_v × 衰减_v               // 与 query 的群体项同口径，不含折扣
ā   = (1/n) Σ a_v                    // **未加权**平均
```

用未加权平均，是因为**加权平均恰好就是 A 现在的群体项得分**：
拿它当目标线等于「把 A 压到 A 自己」，机制就没有意义。
ā 的语义是「一个普通来源怎么看 A」。

### 3.2 变体 U（默认）：均值以上统一折扣

```text
S+ = { v : a_v > ā }        均值以上
S− = { v : a_v ≤ ā }        均值及以下（完全不动）

对 S+ 里的所有来源乘同一个折扣 f，令压完后的加权结果精确等于 ā：

  (f·A1 + B1) / (f·A0 + B0) = ā
  A0 = Σ_{S+} w_v,  A1 = Σ_{S+} w_v·a_v
  B0 = Σ_{S−} w_v,  B1 = Σ_{S−} w_v·a_v

  ⇒ f = (ā·B0 − B1) / (A1 − ā·A0)
       = Σ_{S−} w_v·(ā − a_v)  /  Σ_{S+} w_v·(a_v − ā)
```

第二个等式是数值安全的关键：分子只对 S− 累加非负项，分母只对 S+ 累加非负项，
不会出现「两个大数相减吃掉有效位」。随机 4000 组的实测误差见 §4 与 §6。

**不做分级惩罚**。早期方案用 `f_v = 1 − μ·(a_v−ā)/(1−ā)`，越接近均值罚得越轻；
作者明确要求「均值以上一律处理」，所以改成统一 f。统一折扣还有一个好处：
它有闭式解、结果可预测，且所有被罚来源的折扣相同，不会出现「谁更热情谁被单独针对」
的额外信息泄露。

### 3.3 变体 P（PerSource，仅对照）

```text
对 v ∈ S+：f_v = ā / a_v
```

逐条把读数压到 ā。它看起来更「精准」，但权重也一起变了：S− 完全不动，
S+ 被压得越狠，低分来源在分母里的占比反而越大，所以最终加权结果会**过冲到 ā 以下**。
实测 S3 收益方比 U 更低（见 §6），但注意「低于 ā」不等于「低于诚实均值」——
ā 本身已被攻击者抬高。因此只保留为对照变体，默认不启用。

### 3.4 多攻击者：取最小值，不连乘

```text
f_v = min over A of f_v^A
```

**不连乘**：连乘会复合放大——两个各罚 50% 就变成 75%，三个 87.5%，误伤没有上界。
取 min 让每个来源的惩罚不超过「最严厉的那个攻击者」，有上界、可预测，
符合「宁可漏罚，不可错杀」的取舍。

### 3.5 边界（全部有测试）

| 条件 | 处理 | 理由 |
|---|---|---|
| S+ 为空（所有 a_v 相同） | f = 1 | 没有相对高低，机制自动退出 |
| S− 为空 | f = 1 | 防御性；均值性质保证真实数据里不会发生 |
| S− 权重和为 0 | f = 1 | 统一缩放对加权平均无效（防御性） |
| `A1 − ā·A0 ≤ eps` | f = 1 | 没有可压缩的差距，强行求解只会放大噪声 |
| f < 0 或 f > 1 | 夹到 [0,1] | 不奖励、不变负 |
| f 非有限（NaN/±inf） | f = 1 | 绝不污染全表 |
| G_A ≤ ā（本来没被放大） | f ≥ 1 → 夹成 1 | 不用管 |
| badlist 里的账户没 intern 过 | 所有 a_v = 0 → S+ 空 | 读不到观点，不罚 |
| 读数 NaN/inf | 当 0 | 「损坏」=「没表态」 |
| 权重 NaN/inf/≤0 | 跳过该来源 | 不参与 P0..P3 |
| `badlist_ema` 非法 | 按 1（不平滑） | 默认行为优先 |
| `badlist_mu_max` 非法 | 按 1（完整惩罚） | 默认行为优先 |

### 3.6 自动退出：机制只在「有人比平均更亲近 A」时生效

均值性质保证 **S− 永远不空**：至少有一个 a_v ≤ ā。所以真正会触发的退出条件是
**S+ 为空**，即所有人对 A 的读数完全一样——不管一样地高还是一样地低。

这正是「整个圈子都包庇 A」的情形：没有谁比平均更热情，也就没有相对高低，
f = 1，机制什么也不做。**这不是 bug，是机制的信息边界**：它只能看见「相对」，
看不见「绝对」。这种情形只能靠应用层兜底（例如把 A 直接拉黑、或降低对整圈来源的信任）。

现实数据里读数有噪声，S+ 通常非空；但只要大家的「净超额」互相抵消（G_A ≈ ā），
闭式解给出的 f 就接近 1，惩罚很轻。§6 的中心对照会给两种数字：
精确一致（f 严格 = 1）和真实噪声（平均折扣接近 1，但个别最热情的来源会被压）。

### 3.7 折扣的存储、传播与恢复

- **不改 PositiveList**：原始评分永远是我自己的表态；折扣只存在引擎的
  `BTreeMap<AccountIdx, Score>` 里，缺省 1.0；
- `query` 的群体项权重变成 `份额 × 衰减 × discount[v]`；
- `export_view` 通过 `query` 生成，所以**折扣会自动进入我发布的观点**，
  下游看到 A 的份额随之下降——惩罚必须传播，否则等于没罚；
- `tick` 开头重算；
- **EMA**：`discount ← discount^(1−α) · f^α`。α = 1 时直接等于 f；
  α < 1 时惩罚更慢，但清空 badlist（f = 1）后会逐轮几何式回到 1，误报可自然恢复；
- 存储下限 `MIN_DISCOUNT = 1e-6`：0 是 EMA 的吸收态（`0^(1−α)=0`），
  会让「压到 0 之后再清空」永远回不来。存 1e-6 在权重上等价于静音，但能恢复；
- 折扣表为空时 `query` 完全跳过查表与乘法（默认路径零额外开销）。

### 3.8 新增配置

| 配置 | 默认 | 含义 |
|---|---:|---|
| `badlist_mu_max` | 1.0 | 惩罚强度上限 λ：`f_eff = 1 − λ(1−f)`。λ=1 精确压到 ā，λ=0 关闭 |
| `badlist_ema` | 1.0 | EMA 系数 α ∈ (0,1]；1 = 不平滑 |
| `badlist_mode` | `Uniform` | U（默认）/ P（对照） |

名字沿用作者定的 `badlist_mu_max`；U 的闭式解里已经没有 μ，这个旋钮现在表示
「最多用多大力气」，默认 1.0 时结果与闭式解完全一致。

## 5. 仿真设计

- 世界：`n_initial=420`、`steps=600`、`join_rate=0.10`、无休眠/无流失/无昼夜节律；
  `Infiltrator` 渗透率 10%，t=200 收买声誉最高的一批账户，被推广收益方 A 的质量 0.05~0.15；
- 规模：8 个 seed，每个约 **470~490 个账户**（420 初始 + 约 60 加入 + 收益方），
  42 个购买者，诚实观察者约 430~445；
- 每个存活账户都建一个真 `Engine`（**攻击者也建**）；按世界最终评分同步正分清单；
- 所有观点交换在 t=0 完成（3 轮 × 每轮 24 次抽样），避免衰减混淆；
- 最后一轮后手动 `recompute_badlist()`，让折扣与最终观点一致；
- 诚实观察者的 badlist = `[A]`（**单条**，只放收益方；购买者不放进去）；
- 指标：
  - S3 收益方 = 观察者给 A 的份额 ÷ 该观察者给所有诚实账户的平均份额；
  - S3 攻击者 = 观察者给 42 个购买者的平均份额 ÷ 诚实均值；
  - ρ = 观察者对诚实账户的信任 vs 账户真实 quality 的 Spearman；
  - 被罚来源平均折扣 = 所有 discount < 0.999 的来源的折扣均值（按观察者平均）；
  - 误伤率 = 诚实来源里 discount < 0.9 的比例（分母 = 有观点的诚实来源）；
  - 攻击者来源平均折扣 = 42 个购买者作为来源时的折扣均值。

**口径警告**：绝对 S3 比值受已知的「群体项分母只算已缓存观点」问题影响
（见 `审计/审计总账.md` §1.1），所以本报告只比较**同一口径下 badlist 的增减**，
不把 4.x 倍当作「S3 是否达标」的结论。

## 7. 误伤量化

- **主场景**：U 的诚实来源误伤率 11.1%（discount < 0.9），P 为 8.4%；
  被罚来源平均折扣 U=0.720、P=0.485（混合攻击者与诚实来源）。攻击者来源平均折扣 U=0.736、P=0.266。
  也就是说 U 把攻击者的**话语权**削掉约 26.4%，但只有约一成的诚实来源被削到 0.9 以下。
- **误报压力测试（中心对照）**：把一个真实、高质量、被最多人评分的诚实账户 A 错放进
  badlist，U 的来源平均折扣 0.979，诚实来源 <0.9 比例 8.7%，
  A 的平均份额相对下降 4.1%，但单个最热情的来源最大被压掉 0.61（折扣 0.39）。这说明「错告一个中心账户」在聚合层面伤害有限，
  但会精准打击少数最支持它的人——误报的代价是不对称的。
- **错罚购买者**（把 42 个购买者本人放进 badlist，而不是收益方）：
  误伤率 90.9%，S3 收益方只降 5.1%。原因：购买者本人是**来源**，
  罚他们的「话语权」不会直接降低 A 的得分；而他们作为高声誉老账户，被大量诚实来源信任，
  于是这些诚实来源成了 S+，被大面积误伤。**badlist 的目标必须是「被推广的收益方」，
  不是「收钱办事的人」**。
- **只让一半观察者启用**：S3 降幅约为全量的一半（8.9% vs 17.8%），
  误伤率也接近减半（6.2%）。机制是线性的，没有网络级相变。

## 8. 结论：值不值得留

**值得保留，但定位要准确。**

### 8.1 它做到了什么

1. **削掉攻击放大的约五分之一**：S3 收益方 4.288 → 3.524（17.8%），
   8 个 seed 方向一致（见主表）。
2. **排序质量不降**：ρ 0.3385 → 0.3382（-0.0003）。
   它没有把诚实账户的排序搞乱。
3. **攻击者的话语权显著下降**：攻击者来源平均折扣 0.736（约 -26.4%）。
4. **误伤可控**：约 11.1% 的诚实来源被削到 0.9 以下；中心误报场景的聚合影响更小。
5. **零默认成本**：badlist 为空时，`query` 的折扣分支完全跳过，行为与改造前逐位一致；
   不引入新依赖、不做 I/O、不改 β/份额/压缩格式。

### 8.2 它做不到什么

1. **不能把 A 压回诚实均值**：目标线 ā 是**未加权平均**，而攻击者本身就在样本里，
   会把 ā 抬高。10% 的攻击者 ≈ 把目标线抬高 0.1 量级。所以 U 只能削掉「相对于平均来源
   的超额」，削不掉「平均来源本身已经被污染」的那部分。这是作者定的 ā 口径的直接后果，
   不是实现 bug；要更强只能改目标线（例如中位数/截尾均值），但那会改变已拍板的算法。
2. **不改购买者本人的声望**：S3 攻击者 2.080 → 2.069，几乎不动。
   badlist 削的是他们**影响别人**的能力，不是别人对他们的评分。
3. **抓不到「整个圈子一致包庇 A」**：S+ 为空时机制自动退出；现实噪声下只是 f≈1。
   这是相对机制的固有盲区，只能靠应用层。
4. **依赖应用层的判断**：错罚购买者的误伤率 90.9% 说明，badlist 的输入一旦错了，
   代价比收益大得多。

### 8.3 建议

**为什么默认 U 而不是 P？** 虽然 P 在本次仿真里压得更狠（2.043 vs 3.524）、误伤率还略低
（8.4% vs 11.1%），但它没有目标线保证：P 把每条 S+ 压到 ā，S− 不动，最终加权结果
必然低于 ā，过冲幅度随分布变化、没有上界；U 的闭式解保证结果精确等于 ā。
在「A 是中心」的误报场景里，P 会按 `ā/a_v` 打击最热情的诚实来源，尾部伤害比 U 更重。
P 的 ρ 也略低（-0.0021 vs -0.0003）。如果作者的优先级是「尽可能压攻击」而不是
「精确回到平均」，P 值得单独评估；但作为默认机制，U 的可预测性更重要。

- **保留变体 U**，默认 `badlist_mode=Uniform`、清单为空、`badlist_mu_max=1.0`、
  `badlist_ema=1.0`；只有应用层有高置信度「A 正在攻击我」时才 `set_badlist([A])`。
- **不要默认打开**，更不要用「可疑名单」批量喂进来：误报的中心账户虽然聚合伤害小，
  但单个最支持它的诚实来源折扣会降到 0.39~0.5，属于不对称伤害。
- **不要用 P**：它会把 A 压得比 U 更低（2.043），过冲不可控；
  「过冲」是相对 ā 而言，不代表 A 已经回到诚实水平。
- **不要把购买者本人放进 badlist**：误伤 90.9%，几乎不降 A。
- 如果未来要提升效果，优先讨论「目标线是否该用稳健均值」；在 ā 口径不变的前提下，
  本机制的上限就是现在这个数。
