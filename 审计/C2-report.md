# C2 · badlist 从「清单」改为「一次性事件」

> 工作树：`wt/c2_report`（分支 `feat/c2-report`）
> 复现：`crates/engine` 下 `cargo test`；`crates/exp` 下
> `cargo run --release --bin c2_report -- --seeds 8 --n 420 --steps 600 --rounds 3 --samples 24`
> 原始输出：`crates/exp/c2_result.txt`
> 状态：引擎重构、26 条 badlist 测试、8 seed 对比、持久性实验均已完成。

---

## 0. 一页结论

作者的决定是「可能并不需要 list，只有受到攻击的时候调用一个方法来降低打分」。
C2 把 C1 的「坏账户清单 + 每 tick 自动重算」彻底改成**一次性事件**：

| 问题 | 答案 |
|---|---|
| 新接口 | `report_bad_account` / `penalty_of` / `clear_penalties`，共 3 个 |
| 还保存清单吗 | **不保存**。引擎只保存每个来源的折扣，不知道谁被报告过 |
| 折扣会复合吗 | **不会**。写入规则是 min，重复报告同一个账户不会越压越狠 |
| 会自动恢复吗 | **不会**。tick 不碰折扣；只能由应用层手动 `clear_penalties` |
| 没人调用时 | 折扣表为空，query 完全跳过折扣分支；539 条测试全绿，逐位基线不变 |
| C1 vs C2 | S3 收益方 3.524 → 3.487；误伤 11.1% → 19.7%；ρ 0.3382 → 0.3381 |
| 变差了吗 | **S3 略好、误伤明显变差**；原因见 §6.1，不是实现错误，是 min + 事件语义的直接后果 |
| 建议 | 保留事件 API；应用层**不要每 tick 都报告**，只在确认攻击/有新证据时报告一次 |

一句话：**事件版更「记仇」——它把每一次报告时的判断都取最小值保留下来，
而 C1 每轮覆盖重算，会释放已经不再高于平均的来源。所以每 tick 报告时
S3 只多降 1.05%，诚实来源误伤却从 11.1% 升到 19.7%（约 1.8 倍）。**

## 1. 新 API

~~~rust
impl Engine {
    /// 报告一个「已确认的坏账户」：按当前观点，把「对这个账户比平均更亲近
    /// 的来源」打分压低。返回被实际压低的来源数量。
    pub fn report_bad_account(&mut self, idx: AccountIdx) -> usize;

    /// 某来源当前的折扣，[0,1]，1 = 未受罚。
    pub fn penalty_of(&self, idx: AccountIdx) -> Score;

    /// 手动清空全部折扣（应用层显式撤销，不是自动恢复）。
    pub fn clear_penalties(&mut self);
}
~~~

语义细节：

- **事件**：调用时按**当前**观点缓存算一次统一折扣 f，写进折扣表；引擎不保存
  「A 是坏账户」这件事。观点后来变了，也不会自动重算。
- **min**：`penalty[v] = min(penalty[v], f)`。同一个时刻、同一批观点重复报告，
  第二次起返回 0，折扣逐位不变（有测试）。
- **没有自动恢复**：`tick` 不重算、不漂移、不清表；折扣一旦写下就保持不变。
  `clear_penalties` 只能由应用层显式调用（例如误报申诉成功）。
- **时间基准**：`report_bad_account` 没有 `now` 参数，用引擎最近一次带时间的
  调用（`tick` / `rate` / `on_view` / `probe` / `prune_stale`）作为衰减基准。
- **只影响群体项**：不改 `PositiveList`、不改份额、不改抽样/覆盖率/live 判定。

删除的旧接口：`set_badlist` / `add_badlist` / `clear_badlist` / `badlist` /
`badlist_discount` / `recompute_badlist`，以及 `badlist` 字段、
`badlist_ema`、`badlist_mode`、`BadlistMode`、变体 P、EMA 与存储下限
`MIN_DISCOUNT`。

## 2. 算法（与 C1 相同）

### 2.1 读数与权重

对每个参与群体项的来源 v（我给它正分、有观点缓存、权重 > 0）：

~~~text
a_v = 观点[v] 对坏账户 A 的读数     // 除以 total_mass，夹到 [0,1]，低于噪声底视为 0
w_v = 份额_v × 衰减_v               // 与 query 的群体项同口径，不含折扣
ā   = (1/n) Σ a_v                    // **未加权**平均
~~~

ā 是「一个普通来源怎么看 A」。不用加权平均，是因为加权平均恰好是 A 当前的
群体项得分，拿它当目标线机制就没有意义。

### 2.2 闭式解

~~~text
S+ = { v : a_v > ā }       均值以上
S− = { v : a_v ≤ ā }       均值及以下（完全不动）

A0 = Σ_{S+} w_v    A1 = Σ_{S+} w_v·a_v
B0 = Σ_{S−} w_v    B1 = Σ_{S−} w_v·a_v

f = (ā·B0 − B1) / (A1 − ā·A0)
  = Σ_{S−} w_v·(ā − a_v) / Σ_{S+} w_v·(a_v − ā)
~~~

第二个等式的写法只累加非负项，避免「两个大数相减吃掉有效位」。
把 S+ 里所有来源的权重乘 f 后，全体加权平均精确等于 ā。

强度：`f_eff = 1 − λ·(1 − f)`，λ = `penalty_strength`，默认 1.0。

### 2.3 事件与 min

一次报告只处理一个坏账户：算出 f，对 S+ 里每个来源做
`penalty[v] = min(penalty[v], f_eff)`。重复报告同一个账户、或报告多个账户，
都不会连乘；每个来源的折扣永远不超过「历史上最严厉的那一次」。

注意「不复合」的精确含义：**同一批观点**下重复报告不会更狠（第二次返回 0）；
但跨轮次观点变化后重新计算出的 f 可能更低，min 会保留更低值。这不是同一个 f
的复合，而是不同证据下取最小值。仿真的每 tick 报告就是这种情形，见 §6.1。

### 2.4 边界（全部有测试）

| 条件 | 处理 | 理由 |
|---|---|---|
| S+ 为空（所有 a_v 相同） | f = 1，不写表 | 没有相对高低，机制自动退出 |
| S− 为空 / S− 权重和为 0 | f = 1 | 防御性；统一缩放对加权平均无效 |
| A1 − ā·A0 ≤ eps | f = 1 | 没有可压缩的差距 |
| f 越界 / 非有限 | 夹到 [0,1] / 按 1 | 不奖励、不变负、不污染全表 |
| 坏账户没 intern 过 | 返回 0 | 读不到任何观点 |
| 权重 NaN/inf/≤0 | 跳过该来源 | 与 query 的参与条件一致 |
| penalty_strength = 0 | 返回 0，不写表 | 等于从未调用 |
| 已有更低折扣 | 保留旧值，返回 0 | min 语义，重复报告不复合 |

### 2.5 持久性

`tick` 里没有任何折扣代码：不重算、不漂移、不清表。折扣是**持久状态**，
只有 `report_bad_account` 会降低它、`clear_penalties` 会整体清空。
这是作者明确要的取舍：**误报的代价是永久的**，库不替应用层猜测何时该撤销。

## 5. 仿真设计

- 世界与 C1 完全相同：`n_initial=420`、`steps=600`、`join_rate=0.10`、
  `Infiltrator` 10%、8 个 seed，每个约 470~490 个账户，42 个购买者。
- 每个存活账户一个真 Engine（攻击者也建）；按世界最终评分同步正分清单；
  t=0 交换 3 轮 ×每轮 24 次抽样。
- C2 的调度：每轮先导出观点快照，然后每个诚实观察者 `tick`，**紧接着**
  对收益方 A 调用一次 `report_bad_account`，最后才 `on_view`。
  这正好是 C1 里 tick 开头自动重算折扣的时刻，因此两者看到的观点集合、
  衰减基准、惩罚生效时点完全一致，差别只剩「清单覆盖写 vs 事件 min」。
- 收尾再报告一次，对应 C1 的 final recompute。
- 指标口径与 C1 相同：S3 收益方、S3 攻击者、Spearman ρ、被罚来源平均折扣、
  诚实来源 `penalty < 0.9` 比例。

## 6. C1 / C2 对比

| 指标 | C1（清单版，每 tick 重算） | C2（事件版，每 tick 报告） |
|---|---:|---:|
| S3 收益方 | 3.524 | 3.487 |
| S3 攻击者 | 2.069 | 2.062 |
| ρ | 0.3382 | 0.3381 |
| 被罚来源平均折扣 | 0.720 | 0.718 |
| 误伤（诚实来源 <0.9） | 11.1% | 19.7% |

逐 seed 明细（C2 的无报告行 4.288 / 2.080 / 0.3385 与 C1 的「无 badlist」行
数值完全一致，说明仿真口径未变）：

| seed | C1 U 的 S3 | C2 的 S3 | C1 误伤 | C2 误伤 | C2 平均折扣 |
|---:|---:|---:|---:|---:|---:|
| 1 | 3.926 | 3.884 | 10.6% | 19.2% | 0.728 |
| 2 | 3.288 | 3.254 | 10.9% | 20.8% | 0.718 |
| 3 | 3.643 | 3.603 | 12.8% | 21.0% | 0.715 |
| 4 | 3.545 | 3.506 | 10.0% | 17.8% | 0.713 |
| 5 | 3.263 | 3.224 | 11.4% | 19.4% | 0.727 |
| 6 | 3.579 | 3.543 | 10.7% | 18.8% | 0.716 |
| 7 | 3.373 | 3.344 | 10.4% | 19.6% | 0.705 |
| 8 | 3.578 | 3.540 | 12.1% | 20.6% | 0.722 |
| 均值 | 3.524 | 3.487 | 11.1% | 19.7% | 0.718 |

C2 的 S3 在 8 个 seed 上**全部**低于 C1，方向一致；误伤也**全部**更高，
同样方向一致。这不是某一个 seed 的噪声。

### 6.1 为什么数字不同

两者的调度、观点集合、惩罚生效时点完全相同，唯一差别是**折扣的更新规则**：

- C1：每次重算都用当前观点**覆盖写** `discount[v] = f_current(v)`。
  某个来源如果不再属于 S+，它会被写成 1，惩罚释放。
- C2：`discount[v] = min(旧值, f_current(v))`。来源一旦被压过，
  即使后来的观点里它不再高于平均，旧折扣也不会释放。

3 轮 + 收尾共 4 次调用（第 1 次还没有任何观点，实际生效 3 次），C2 的折扣集合
因此是历次 S+ 的**并集**（每个来源取各次最小值），C1 的折扣集合只是**最后一次**
的 S+。这带来两个结果：

1. S3 收益方略低（C2 多压了一些来源）；
2. 诚实来源误伤明显上升（早期被误判、后来已经不再「异常热情」的诚实来源
   仍被永久保留折扣）。

这不是 min 写错了：同一个时刻重复报告确实不会更狠（引擎测试验证）；
跨轮次时 f 本来就不同，min 按定义保留更低的那个。作者的「不复合」诉求
针对的是「重复调用把惩罚叠成 0」，本实现满足；而「跨时间的取最小值」
是事件版 + 无恢复的必然结果。

### 6.2 单次报告对照（诊断用，不是 C1 等价）

| 版本 | S3 收益方 | S3 攻击者 | ρ | 被罚来源平均折扣 | 误伤 |
|---|---:|---:|---:|---:|---:|
| C2 单次报告（收尾） | 3.879 | 2.066 | 0.3381 | 0.730 | 13.9% |

单次报告在收尾时才生效，整个交换过程用的是未惩罚的观点，所以传播反馈更弱：
S3 降得少（3.879，远高于 C1 的 3.524）、误伤也少（13.9%，低于每 tick 的 19.7%）。
它说明「什么时候报告」和「报告几次」都会改变结果，应用层不能把
`report_bad_account` 当作每 tick 的例行公事。

注意：这一行**不是 C1 等价**。C1 在第 2、3 轮就已经带着折扣发布观点，
惩罚会通过网络传播；收尾单次报告没有这个反馈回路。

## 7. 惩罚的持久性

作者撤回了自动恢复：`penalty_recovery` 已删除，tick 里没有任何漂移代码。
本节只验证「压下去之后会发生什么」。

### 7.1 经过多个 tick，折扣是否变化

seed 1 报告完（每 tick 报告 4 次）之后只调用 `tick`、不再报告：

| 经过 tick | 诚实来源平均折扣 | 诚实<0.9 | S3 收益方 | S3 攻击者 | 折扣逐位不变 |
|---:|---:|---:|---:|---:|---|
| 1 | 0.944 | 19.2% | 3.884 | 2.101 | 是 |
| 5 | 0.944 | 19.2% | 3.884 | 2.101 | 是 |
| 20 | 0.944 | 19.2% | 3.884 | 2.101 | 是 |
| 100 | 0.944 | 19.2% | 3.884 | 2.101 | 是 |

结论：**1 / 5 / 20 / 100 个 tick 后，折扣逐位不变，S3 也停在被压低的水平。**
（0.944 是「所有诚实来源」的平均折扣，含大量 1.0；被罚来源内部的平均折扣
是 0.728。）引擎测试 `penalties_persist_across_ticks` 与仿真结果一致。

### 7.2 持续攻击下 S3 随轮次

3 个 seed 均值，每轮都 tick + 报告（报告组）与完全不报告（对照组）：

| 轮次 | S3 收益方（无报告） | S3 收益方（每tick报告） | 平均折扣（报告） | 诚实<0.9（报告） |
|---:|---:|---:|---:|---:|
| 1 | 4.924 | 4.924 | — | 0.0% |
| 2 | 4.707 | 4.064 | 0.699 | 0.5% |
| 3 | 4.403 | 3.611 | 0.727 | 14.9% |
| 4 | 4.163 | 3.326 | 0.720 | 20.3% |
| 5 | 3.918 | 3.034 | 0.715 | 21.8% |
| 6 | 3.762 | 2.858 | 0.713 | 22.7% |
| 7 | 3.604 | 2.686 | 0.712 | 22.9% |
| 8 | 3.508 | 2.585 | 0.711 | 23.1% |

没有恢复，所以惩罚不会随时间衰减；报告组的 S3 一旦被压低，就一直低于
不报告组。曲线里没有出现「先降后回升」的反弹。

需要如实指出的第二点：报告组的 S3 从第 3 轮起继续下降（3.611 → 2.585）。
这不是恢复失效，而是**每 tick 继续报告 + min 让折扣集合按轮次累积**：
第 4 轮又压了一批新来源，第 5 轮再压一批。对照组自己也在下降（观点扩散），
但报告组下降得更快、更狠，误伤从 14.9% 爬到 23.1%。这再次说明：
**「没有自动恢复」保证了惩罚持久，但「每 tick 都报告」会让惩罚范围不断扩张。**

### 7.3 误报的代价是永久的

- 一旦某个诚实来源被误压，折扣会一直保留，直到应用层调用 `clear_penalties`；
- 库不会因为「观点变了」「时间过去了」「清单空了」而释放它（根本没有清单）；
- C1 的中心误报压力测试（把真实高质量中心账户错报）得到的来源平均折扣 0.979、
  单个最热情来源最大惩罚 0.61，在 C2 下会**永久保留**，不会自然回弹；
- 作者已明确接受这一点。应用层需要自己做申诉/撤销流程，并在确认误报后调用
  `clear_penalties`（这是手动撤销，不是自动恢复）。

---

## 8. 结论与建议

1. **API 达到目标**：只有 3 个方法，没有清单，没有自动重算，没有自动恢复。
   没人调用时 query 完全跳过折扣分支，逐位一致；539 条测试全绿。
2. **事件本身没有算错**：单次报告仍精确把群体项压到 ā
   （8 个 seed 的探针抽查 max |G_after−ā| = 1.45e-9），折扣不复合。
3. **每 tick 报告会变差**：S3 只多降 1.05%（3.524 → 3.487），误伤却从
   11.1% 升到 19.7%。原因是 min 保留了跨轮次的历史折扣，而 C1 的覆盖写会
   释放已经不再异常的来源。
4. **建议的用法**：应用层只在「确认正在被 A 攻击」或「出现新证据」时报告一次，
   不要每 tick 重复；报告后让折扣持续生效（这正是作者要的持久性）。
   如果误报，走显式的 `clear_penalties`，不要指望库自动恢复。
5. **不建议为了降误伤改回清单/自动恢复**：那会违背作者「不需要 list」的决定。
   若未来确实要折中，应该单独讨论「什么时候允许释放折扣」的应用层策略，
   而不是在引擎里偷偷加漂移。
