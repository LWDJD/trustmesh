# 威胁模型（工程可用性文档）

> 写给**要部署这个库的人**，以及**要评估它能不能用的人**。
> 不是设计文档，不是审计报告——它只回答一件事：**在什么条件下它是安全的，在什么条件下它不是。**

> 生成：2026-11-16。数据来自 [B0-baseline.md](B0-baseline.md)（8 seed 真引擎实测）、
> [A6-ablation.md](A6-ablation.md)、[A8-attack.md](A8-attack.md)、[A13-spec.md](A13-spec.md)。

## 0. 一句话

> **这个库能保证「纯女巫拿不到任何信任」**（S1 恒 0、S2 越线率 0，8/8 seed 逐位）。
> **它不能保证「少量作恶者影响极其有限」**（S3 背书场景 4.37 倍，最坏观察者 8.14 倍）。
>
> 两者都是**结构决定的**，不是实现缺陷。

---

## 1. 它防什么（**已验证成立**）

| 威胁 | 实测结果 | 为什么成立 |
|---|---|---|
| **批量注册的女巫集群自我吹捧** | S1 = **0.00000000 ± 0**（8/8 seed 逐位），出现率 0% | 女巫不在任何诚实账户的正分清单里 ⇒ 抽样抽不到 ⇒ 个人项与群体项都是 0 |
| **渗透者注入全新女巫并给满分** | S2 越线率 = **0 / 7690±191 对**（8 seed），**没有任何一对超过诚实均值** | 影响力预算：份额 = 评分 ÷ Σ评分，注入越多每个越薄（实测 1.66→0.01） |
| **单点声明超额分数（>1）突破预算** | P0② 修复后超发被压回预算内；合规视图逐位不变 | 读数「分子先夹紧再除」，与分母 `Σmin(q,1)` 同口径 |
| **后登记账户被既有观点白送背书** | P0③ 修复后，`idx >= mass_covers` 一律按「没表态」 | `on_view` 时快照已知账户数 |
| **同输入产生不同输出** | S6 = **0.00000000 ± 0**（3 场景 × 8 seed 全部逐位） | 全程 BTreeMap + 固定种子 RNG + 无并行 |
| **跨平台产生不同输出** | MSVC / GNU / **wasm32** 三路实测 `decay()` **逐位相同** | 见 §5 |
| **长期离线导致观点无限期有效** | 攻击残余 600h 后从 0.990（无衰减）降到 0.250（72h 半衰期） | 衰减 = **伤害时效机制**（不是反女巫机制，见 §3） |

## 2. 它**不**防什么（**已知失败项**，部署前必须接受）

### 2.1 S3：背书攻击**结构上不可能被压到 1 倍以内**

**攻击形态**：40 个渗透者（占 8%）各自给同一个同伙打满分，然后正常传播。

**实测**：

| 指标 | 8 seed 均值 ± sd | 最坏观察者 |
|---|---:|---:|
| 收益方 / 诚实均值（渗透场景） | **1.8207 ± 0.4696** | 4.3396 |
| 收益方 / 诚实均值（**背书场景**） | **4.3742 ± 0.7453** | **8.1360** |
| 攻击者自己 / 诚实均值（渗） | 2.2556 ± 0.2352 | — |
| **解析地板 1/β** | **3.3333332** | — |
| 实测 ÷ 地板（渗 / 背） | **0.546 / 1.312** | 1.302 / **2.441** |

**为什么不可能压到 1**：β = 0.3 时，只要观察者自己评过收益方、且群体项把它顶满：

~~~text
D[T] = β/N + (1−β)/N = 1/N     （T = 收益方）
D[H] = β/N                      （H = 我评过但没人背书的诚实账户）
比值 = 1/β = 3.3333332
~~~

**并且 S3 的 98%~99% 由群体项贡献**（渗透 `personal 0.0378 + group 1.7578`；
背书 `personal 0.0280 + group 4.2881`）⇒ **想改善只能动 β 或群体项口径**，动个人项毫无意义。

**怎么读这个数**：不要读「4.37 倍 → 失败」，要读「**相对地板 1.31 倍**」。
* 渗透场景 0.546 倍：群体项没把收益方顶满（覆盖率不足、衰减稀释），**可以考虑接受**；
* 背书场景 1.312 倍：**超过了 β 能解释的范围**，最坏观察者 2.44 倍——这是**已知的、未修的**放大通道。

**缓解手段（都需要作者决策，不是 bug 修复）**：
- 提高 β（0.3 → 0.9 可让 S3 降到 0.355/0.728，但代价是群体话语权从 70% 降到 10%，**圈子化加剧**）；
- 改分母口径（收缩群体项）；
- 接受它，写进应用层的风险告知。

### 2.2 S4：空账户能拿到少量声望（结构性）

| 指标 | 8 seed 均值 ± sd |
|---|---:|
| 空账户均值 / 诚实均值 | **0.007720 ± 0.003855** |
| 空账户**单点最高** / 诚实均值 | **0.308805 ± 0.154202** |
| 空账户出现率 | **2.50% ± 0**（每个观察者 40 个里 1 个） |

**根因**：Count Sketch 里「精确的 0」与「不存在」不可区分（碰撞噪声）。

**⚠️ 这条强依赖清单长度 m**（`审计/A3-view.md` 实测）：

| m（发布端正分清单长度） | 出现率 | 拿走的信任 | 最好空账户 ÷ 真实均值 |
|---:|---:|---:|---:|
| 100 | 0.44% | 0.059% | 0.35 |
| 300 | 6.96% | 0.408% | 0.593 |
| 1000 | **30.4%** | **2.14%** | **1.331** |

**B0 的场景是 m ≈ 18**，所以在小清单下 S4 看起来还行。**真人规模（m ≥ 300）会迅速恶化。**
⇒ **部署前必须确认你的清单长度**；m > 300 时 S4 是真实威胁。

### 2.3 S5：单来源伪造观点能抬高自己 83%

| 指标 | 8 seed 均值 ± sd |
|---|---:|
| 自吹（视图只写自己 1.0） | **1.828634 ± 0.072609** |
| 自吹 + 塞 200 个已认识空壳 | 0.993680 ± 0.004431 ✅ |

「塞壳」防线有效（把 `total_mass` 撑大没用），但**纯自吹仍然有 83% 收益，且 P0 之后未改善**。

### 2.4 重放旧观点可刷新新鲜度（A8 D4，**未修**）

`on_view` 不比较 `published_at` 的任何单调性，同一份旧观点可以反复提交、无限刷新 `last_check`。
实测 group 0.25 → 0.997（×4.0）。

**这是刻意保留的**：判断「这份观点是不是更新」需要应用层签名/时间戳，属于应用层职责。
**部署时必须由应用层保证 `on_view` 只投递真正的新观点。**

## 3. 衰减的正确理解

> **衰减不是反女巫机制。** A4 实测：对 S1/S2/S4/S6 的净贡献 ≤ 4%，**置信区间全部跨 0**。

**它的唯一一阶效应是伤害时效**：

| 配置 | 攻击结束 600h 后的残余 |
|---|---:|
| 关衰减 | 0.990 |
| 半衰期 72h | **0.250** |

**副作用**（必须接受）：衰减引入 **S5 陈旧套利**——攻击者保持新鲜、诚实来源陈旧 60h 时，
单来源影响力上限被放大 **1.60×（H=72h）/ 3.40×（H=24h）**。

**并且衰减对「全体一起变旧」完全免疫**（加权平均的性质）：整个社区都离线时，结果不变。
所以它**达不到**「防止长期离线账户影响」这个原始目的——那个目的需要覆盖率机制（已被否决，见 §6）。

## 4. 抽样节奏：**这是部署时最容易搞砸的地方**

> A10 实测：n=600、k=8、T=30h → 刷新周期 **2250h = 93.75 天**，而半衰期只有 72h。
> 结果：**90.7% 的来源衰减因子 < 0.1，ESS 从 600 掉到 55.8**。

**硬约束**：

~~~text
刷新周期 P = (n_list / k) · T   ≤   H / 2
⟹  k ≥ 2 · n_list · T / H
~~~

| 你的清单长度 | T=12h 时的最小 k | 每轮带宽（40KB/视图） |
|---:|---:|---:|
| 100 | 34 | 1.3 MB |
| 300 | 100 | 3.9 MB |
| 1000 | 334 | 13.0 MB |
| 3000 | 1000 | 39 MB |

**违反这条的后果不是「慢」，是「衰减变成噪声」**：这时候你看到的群体项其实只由最近抽到的那几十个人决定。

→ 用 `Engine::recommended_k()` 与 `Engine::freshness_budget()` 自查（见 `crates/engine/src/budget.rs`）。

## 5. 跨平台确定性（已验证）

结果需要在不同平台间可复现，所以浮点必须逐位一致。本库唯一的平台相关浮点调用是
`crates/agg/src/lib.rs` 的 `0.5f64.powf(dt/H)`。

**2026-11-16 三路实测**（14 个时间点，H=72h）：

| 平台 | 结果 |
|---|---|
| x86_64 MSVC（Windows libm） | 位模式基线 |
| x86_64 GNU（MSYS2 libm） | **逐位相同** |
| **wasm32**（`wasm32-unknown-unknown`，Node v24 实跑） | **逐位相同** |

关键点：整数倍半衰期落在精确可表示值上（`dt=72 → 0x3f000000` = 0.5；`dt=144 → 0x3e800000` = 0.25；
`dt=36 → 0x3f3504f3` = 1/√2）。非整数倍也三平台一致。

**残留风险**：这只证明「这三种 libm 一致」，不是「所有 libm 永远一致」。
若要彻底消除熵源，可把 `powf` 换成纯算术实现（全仓只有这一处用法，约 40 行）。

## 6. 已被否决的机制（**别指望它们**）

| 机制 | 为什么否决 |
|---|---|
| 两级衰减 / 覆盖率 / 有替代才剔除 / N_min | 验收线 +10pp，实测 **+32~52pp**（方向相反）。已删（`568fc4d`） |
| 负评分 | 作者砍掉：负分占配额 → 负分攻击 → 一堆负分 ID 就能 DDoS |
| banlist（作者原话第 32/35 行） | **归应用层**。实测也无效：λ 从 1 扫到 30，污染比只从 1.579 动到 1.548（均匀降权被加权平均吃掉） |
| 份额 cap 2× 均值 | 完全无效（ΔS3 −0.004）：满分来源份额只有均值的 1.88 倍，够不到 2.0 的 cap |
| Median / WeightedMedian / Trimmed 聚合 | 前两个把群体项**打成 0**（伪防御），第三个让 S3 **更差 +0.374** |
| 「提高 β 无效」 | **这条旧结论是错的**。真引擎上 β 0.3→0.9 让 S3 从 1.695 降到 0.355 |
| 小清单保守降级（B1） | S3 能降 50%，但 ρ 掉 13~26%，且**压得住分数压不住排名** |

## 7. 部署检查清单

**必须确认**（不满足就是误用）：

- [ ] **清单长度** ≤ 300（否则 S4 崩；m=1000 时 30.4% 空账户进分布）
- [ ] **抽样节奏**满足 `(n_list/k)·T ≤ H/2`（用 `recommended_k` 自查）
- [ ] **`on_view` 只投递真正的新观点**（重放会刷新新鲜度，D4 未修）
- [ ] **应用层保证观点来源可信**（库不验签、不验 owner，A8 实测任意 40KB 数组都是合法观点）
- [ ] **接受 S3**：背书场景可达 4.37 倍、最坏观察者 8.14 倍
- [ ] **限流/防 DDoS/内容托管**由应用层负责（库**零**此类代码，见 `设计规格.md` §0.2）

**推荐配置**：

~~~rust
EngineConfig {
    beta: 0.3,               // 作者定，不可改
    half_life: 72,           // 小时；衰减是伤害时效，别指望它反女巫
    view_params: ViewParams { buckets: 2048, hashers: 5, seed: 0 },
    agg_mode: AggMode::Mean, // 其它三个实测更差或伪防御
    noise_multiplier: 1.0,   // 实测门限恒为 0，等于没开；保持默认
    decay_enabled: true,
    decay_floor: 0.0,
    ..Default::default()
}
~~~

## 8. 一句话给决策者

> **这个库的强项是「不给陌生人白送信任」**——纯女巫、批量注册、超额声明、后登记账户，这四类攻击都被结构挡住了，实测逐位为 0。
>
> **它的弱项是「熟人背叛」**——一个被 8% 的渗透者集体抬举的同伙，能拿到 4.37 倍、最坏 8.14 倍的诚实用户可信度。这是 β=0.3 的算术后果，不是 bug。
>
> **如果你的场景是「防陌生人刷分」，它可用。**
> **如果你的场景是「防内部串谋」，它不可用**，或者你必须同时把 β 提到 0.7~0.9 并接受圈子化。
